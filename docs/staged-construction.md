# Поэтапное построение

Цикл агента: «план → справка API → этап → независимое чтение → следующий этап».
Исполнение остаётся Python/MCP, с одним STA и таймаутом COM 55 секунд.

## План и код

Перед построением модель вызывает `set_construction_plan`:

```json
{"stages":[{"id":"profile","title":"Профиль втулки","expected_result":"Управляющие радиусы и длина"},{"id":"revolve","title":"Вращение","expected_result":"Одно тело"}]}
```

До 32 этапов; ID уникальны. Можно менять, удалять и переставлять только ещё не
начатые этапы. Предыдущие редакции сохраняются. Статусы `pending`, `running`,
`done`, `error`, `stopped` определяет приложение. Один `execute_python` завершает
этап; ограниченное исправление ошибки может продолжить ошибочный этап с тем же ID.
Без `stage_id` у Python приложение выбирает первый ожидающий этап или добавляет
новый. Готовые инструменты изменения (`create_part`, `set_dimension` и другие)
получают отдельные автоматические этапы и не завершают запланированный Python-этап.
Их ID и результат возвращаются модели в `construction_stage`. Они помечены
`application_owned`; приложение сохраняет их при пересмотре плана, даже если модель
их не перечисляет. Изменять их нельзя; общий лимит 32 включает служебные этапы.
До каждой мутации этап уже записан.
Во время исправления запланированного Python-этапа дополнительный вызов без
`stage_id` получает отдельный автоматический этап: он не занимает следующий
ожидающий этап и не подтверждает исправление. Продолжение должно явно указать
ID ошибочного этапа; после его успеха ошибки предыдущих попыток этого этапа
помечаются исправленными. Дополнительный Python по-прежнему учитывается как
потенциальное изменение, расходует лимит и требует проверки; признак только чтения
из текста кода не выводится.
Native `add_mate` проверяется по вложенным сопряжениям через `inspect_cad`
до/после создания: новое имя, тип, отсутствие подавления и ошибок. Эти два чтения
резервируются в лимите до мутации; верхний уровень дерева для этого недостаточен.

```json
{"code":"result = length_mm","stage_id":"profile","checks":[{"kind":"dimension","name":"Length@Profile","value":40,"unit":"mm"},{"kind":"body_count","expected":1}]}
```

Это форма аргументов, не готовое построение. Имя размера берётся из документа.
Модель видит `code`, `stage_id`, `checks`; служебные инструменты и ID Python-сессии
скрыты и не попадают в события или sidecar.

## Python-сессия

Окружение создаётся лениво после разрешения Python и живёт один Run. Переменные,
функции, импорты и COM-ссылки сохраняются, включая частичное состояние после
известной ошибки. Новый запрос получает новое окружение. Прямой
`execute_python(code)` без служебной сессии остаётся независимым.

Перед фрагментом проверяется закреплённый SolidWorks, обновляются служебные
`swApp`, `model`, `GET`, `MM`, `NOTHING` и другие помощники. Закрытый документ
другим не подменяется; внешнее переключение активного документа останавливает
фрагмент до исполнения. `result` очищается, чтобы не выдать старый результат за новый.

При `create_part`/`create_assembly` приложение подставляет скрытый `session_id`,
если Run уже имеет Python-окружение. Внутри той же команды STA сервер закрепляет
точный COM-объект, возвращённый `NewDocument`; переменные и прежние COM-ссылки
сохраняются. Дальнейшее исполнение разрешается только после независимых проверок
создания. Переименование при «Сохранить как» не меняет идентичность. Подмена
другим документом с тем же именем, закрытие или внешнее переключение запрещают
следующий фрагмент. Неизвестный session_id отклоняется до `NewDocument`.
Модель не получает служебные аргументы или ID сессии; прямые create без ID независимы.

Явный `open_document` также закрепляет точный объект в текущем окружении.
`OpenDoc6` сам не активирует уже загруженную деталь. Поэтому инструмент один раз
вызывает `ActivateDoc3` без модального перестроения, проверяет полный путь,
уникальность заголовка и совпадение возвращённого/активного COM-объектов.
При неоднозначности продолжение запрещено. Приложение резервирует ещё два
независимых чтения активного документа и списка путей до открытия. Отказ проверки
блокирует следующий Python; переменные сессии при успешном открытии сохраняются.

Размеры создаются внутри `with DIMENSIONS():`. Контекст временно отключает
`swInputDimValOnCreate`, иначе `AddDimension2` может открыть модальное окно.
При известном исходе настройка восстанавливается даже после исключения.
После unknown новые COM-вызовы, включая восстановление настройки, запрещены.

`TRANSFORM_POINT(point, matrix)` применяет `MathTransform.ArrayData` к трём координатам
в метрах без дополнительного обращения к `MathUtility`. Матрица содержит 16 конечных
чисел; используется порядок SolidWorks: вращение, перенос, масштаб.

При любом завершении окружение освобождается на STA. После таймаута освобождение
ставится за исходным worker без новых обращений к CAD; неопределённость не
сбрасывается. При закрытии stdio сервер освобождает оставшиеся окружения и ждёт
естественного выхода worker. Namespace не сериализуется: восстановление sidecar
возвращает историю и этапы, но требует новой инспекции CAD для продолжения.

## Справка и примеры

- `search_solidworks_api(query)` ищет интерфейсы, методы, свойства и перечисления
  в установленных `sldworks.tlb`/`swconst.tlb`.
- `get_solidworks_api(symbol_id, include_help=false)` возвращает порядок аргументов,
  исходные COM-описания типов, флаги и версию. Примеры ID:
  `IFeatureManager.InsertSheetMetalBaseFlange2`,
  `swDimensionDrivenState_e.swDimensionDriving`.
  Имя перечисления целиком, например `swEndConditions_e`, возвращает
  `kind="enum"` и полный список `members` с именами и значениями констант
  из установленной библиотеки. Для него `include_help=true` открывает страницу
  перечисления в официальной справке `swconst`.
- `include_help=true` добавляет пояснение только с `help.solidworks.com`, с
  ограничением ожидания/размера и без redirects. При сетевой ошибке локальная
  сигнатура сохраняется. Сеть не занимает STA.
- `search_cad_examples(query)`/`get_cad_example(example_id)` дают собственные
  рецепты: открытый листовой профиль, отверстия с transform, вращение, фаска,
  вставка компонента, сопряжения. Указаны параметры, предпосылки, API, дерево и проверки.

Библиотеки ищутся в типовом `Program Files/SOLIDWORKS Corp/SOLIDWORKS`; отсутствие
явно возвращается как ошибка. Сетевой текст является справкой, а не инструкцией
для исполнения. Значения перечислений брать из установленной библиотеки.
Отсутствующий `symbol_id` возвращает `found=false` и существующие интерфейсы
того же метода в `alternatives`; сигнатура не выдумывается, сеть не запрашивается.
Это обычный результат справочного поиска. Ошибки CAD продолжают останавливать Run.
Рецепты — фрагменты для адаптации к прочитанному документу. `verified_versions`
пуст до успешной live-проверки соответствующего рецепта. На SolidWorks 2025 SP5
непосредственно исполнены исходные шесть рецептов; подготовка профилей, выбор граней
и размерный эскиз отверстий общие для библиотеки и прямого harness. У обновлённого
`holes-transform` отметка live-проверки снята до исполнения новой версии:
положение размерных надписей теперь преобразуется из эскиза в систему модели
через обратную `ModelToSketchTransform`. Координаты геометрии создаются в эскизе,
а `AddDiameterDimension2`/`AddHorizontalDimension2`/`AddVerticalDimension2`
получают положение надписи в системе модели, в том числе на смещённой грани.

## Проверки

`inspect_cad(sections, dimension_names=[])` читает `features`, `dimensions`,
`bodies`, `sheet_metal`, `surfaces` (цилиндры), `components`, `mates`, без
перестроения и произвольного Python. Единицы — мм/градусы; у компонента отдельно
возвращаются вращение, перемещение в мм и масштаб.

Тип единиц `IDimension.GetType` — `swDimensionParamType_e`: угол имеет значение 1,
линейная величина — 0. Это другое перечисление, чем `swDimensionType_e`, где 3 —
визуальный тип углового размера. Сигнатура и значения сверены с установленной справкой.

| `kind` | Обязательные поля | Проверка |
|---|---|---|
| `feature` | `name` | Наличие; необязательный `type` |
| `body_count` | `expected` | Число тел детали |
| `dimension` | `name`, `value`, `unit` | Значение управляющего размера (`mm`/`deg`) |
| `sheet_metal` | `thickness_mm`, `bend_radius_mm` | Толщина и радиус |
| `cylinder` | `radius_mm`, `count` | Число цилиндрических граней |
| `component` | `name` | Не подавлен; необязательные `path`, `fixed`, `translation_mm`, `rotation` |
| `mate` | `mate_type` | Не подавлено, нет ошибки; необязательные `name`, `components`, `lock_rotation` |

Для положения цилиндра задаются `axis_point_mm` и `axis_direction`. Сравниваются
линии осей: положение исходной точки вдоль оси и знак направления не влияют.
Подсчитываются грани, а не физические отверстия; разделённый цилиндр может иметь
несколько граней. Допуски — 0,001 мм и 0,01°. Усечённое чтение не даёт успешной
проверки. Bbox приблизительный и проверками точных размеров не используется.

Перед мутацией резервируется один вызов инспекции на набор `checks`, включённый
в общий лимит. Некорректные проверки, недостаточный бюджет или отсутствующий
инструмент запрещают мутацию. Несовпадение останавливает Run без повтора.
Успех подтверждает только заявленные свойства: произвольный Python остаётся
`unverified`, даже когда эти проверки прошли. Исходные результаты сохраняются.

## UI и совместимость

Список этапов расположен над журналом; проверки отдельно от статуса, код и
доказательства раскрываются. Русский/английский поддерживаются. Событие
`construction_plan` идёт через SSE `update`, сохраняя seq/replay/gap recovery.
Snapshot и sidecar содержат `construction_plan` и `construction_plan_history`;
у старого файла без полей восстанавливаются пустые списки, версия формата прежняя.

Инспекция сопряжений также возвращает блокировку вращения концентрического
сопряжения и параметры его сущностей: тип, точку в мм, направление и радиусы в мм.
Координаты `IMateEntity2.EntityParams` относятся к системе сборки. Для прямой
приёмки конкретной пары деталей проверяются ровно два исправных сопряжения,
общая ось цилиндров, совпадение плоскостей торцов перпендикулярно оси и отсутствие
блокировки вращения. При одной закреплённой детали это оставляет одно осевое
вращение и запрещает поступательное движение. Этот вывод не распространяется
на произвольные сборки. Недокументированный `GetRemainingDOFs` не используется:
в повторных живых чтениях он возвращал «данные недоступны» даже после сохранения.

Сырой MCP-каталог — **34** инструмента: прежние 27, пять справочных/инспекционных,
два служебных. Модель получает **33**: два служебных скрыты, добавлен локальный план.
При включённой оценке цели приложение добавляет ещё три локальных инструмента
контракта, привязок и визуальной оценки; каталог MCP остаётся прежним.
Этапы и оценка цели работают в одном Run и сохраняются вместе в sidecar.
Итоговый статус Run публикуется после закрытия Python-сессии в обоих режимах.

## Живая приёмка

```powershell
.venv\Scripts\python.exe -m scripts.staged_acceptance --mutate-new-documents
```

Прямой сценарий строит новые кронштейн, втулку и сборку, сохраняет код, результаты
и тестовые файлы во временную папку. Проверяет управляющие размеры, геометрию,
развёртку, редактирование 80→100/Ø30→34, сопряжения и остаточную подвижность вала.
Рецепты открытого листового профиля и вращения содержат `preparation_code` и
`preparation_checks`: профиль выполняется и проверяется отдельным этапом перед
`code`, создающим объёмный элемент. Прямой harness использует те же фрагменты.
Рецепт отверстий содержит полный размерный эскиз `code`, `declared_checks` и
`next_tool=cut_through`; код общего профиля отверстий используется и в harness.
Для сборки `assembly-insert` содержит `shaft_preparation_code`/`shaft_checks`,
а `assembly-mates` — `selection_code`/`selection_parameters` для выбора цилиндров
и торцов в контексте компонента. Их предпосылки ограничены тестовой геометрией.
`--case bracket`/`--case bushing` ограничивают область проверки; поле `scope` в отчёте
не позволяет принять один сценарий за весь набор. При ошибке следующие действия
запрещаются. У файлов уникальные имена, чтобы уже открытая одноимённая деталь
из другого теста не мешала загрузке компонента.

Приёмка через настроенного провайдера:

```powershell
.venv\Scripts\python.exe -m scripts.staged_provider_acceptance --mutate-new-documents --profile-id <ID> --output <новый-каталог>
```

Harness использует настоящий `Agent`/`Provider`/MCP, сохранённое разрешение Python,
лимит 80 и неизменённый сгенерированный код. На первой ошибке он останавливает Run,
сохраняет события и snapshot. Статус `completed_requires_acceptance_review`
обозначает завершение агента, а не автоматическое подтверждение всей геометрии.
Фактические результаты — в [verification.md](verification.md).
