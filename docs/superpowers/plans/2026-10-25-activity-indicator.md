# Индикатор выполнения — план реализации

> Исполнение в текущей сессии через executing-plans и TDD. Вариант утверждён пользователем: компактный этап с таймером и раскрываемые подробности.

**Цель:** показывать фактический этап запроса, длительность ожидания и результаты обращений, чтобы длительное ожидание не выглядело остановкой.

**Подход:** существующие события Agent и опрос состояния API. Добавить время события и события начала/конца обращения к модели; отдельный UI-компонент обновляет таймер раз в секунду. Пульсация обозначает активный запрос при доступном приложении. При потере связи показывать предупреждение. Потоковый ответ и измерение токенов/скорости передачи в этот вариант не входят.

**Ограничения:** русский интерфейс; COM и внешние запросы выполняются как раньше, без повторов и параллельных CAD-вызовов. Секреты, тексты запросов и изображения в новые диагностические события не копируются. Изоляция — существующая рабочая ветка; без публикации.

## Основные риски для проверки

- Таймер не сбрасывается при каждом опросе/перезагрузке.
- При недоступном API пульсация не изображает подтверждённую работу.
- Не появляется повторная отправка запросов или вмешательство в COM.
- Дублирующие tool_result для одной операции не удваивают счётчик.
- Длительное ожидание подтверждения и остановки обозначается отдельно от ожидания модели.
