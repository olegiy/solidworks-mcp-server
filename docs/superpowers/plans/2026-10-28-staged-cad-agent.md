# Поэтапное построение деталей и сборок

План одобрен пользователем 28 октября 2026 года. Цель: Python/MCP-агент с циклом
«план → поиск API → этап → чтение результата → следующий этап».

## Изоляция

Ветка `feat/staged-cad-agent`, база `skills`/`a9234b0`, отдельный worktree.
Незакоммиченные изменения исходного checkout не переносить, не убирать и не
коммитить. Проверить baseline. Все исходники, документы, тесты и коммиты делать
в feature-ветке; оставить для ревью без автоматического merge.

## Задачи

1. Ленивая Python-сессия на Run: переменные/функции/COM-ссылки, независимый прямой
   вызов, скрытый ID, обновление помощников, запрет подмены закрытого документа,
   частичное состояние после ошибки, освобождение в STA после любого завершения
   и неизвестного исхода. Namespace не сериализовать. Таймаут 55 с и один STA.
2. Поиск API из локальной typelib, ограниченный клиент help.solidworks.com,
   собственные примеры открытого листового профиля, отверстий с transform,
   вращения, фаски, вставки и сопряжений. Параметры, предпосылки, API, дерево,
   проверки; версия проверена только после live.
3. `set_construction_plan`: постоянные ID/title/expected_result до первой мутации,
   изменение ожидающих этапов, история редакций. `execute_python(stage_id, checks)`;
   статусы определяет приложение. `inspect_cad`: дерево, управляющие размеры,
   тела, листовые свойства, аналитические поверхности, компоненты/трансформации/
   сопряжения. Контролируемые проверки резервируются до мутации и входят в лимит;
   допуски 0,001 мм/0,01°. Bbox диагностический; подтверждение отдельных свойств
   не делает произвольный Python полностью `verified`.
4. Список этапов над журналом, код/доказательства раскрываются. `construction_plan`
   в SSE/snapshot/sidecar, совместимость старых файлов, seq/replay/gap recovery.
   Сохранить разрешения, приватность, ru/en и stop. Инструкции: именованные
   параметры, технология, размеры/связи, понятное дерево и чтение результата.
5. TDD, Python nonlive/Ruff, настоящий stdio-каталог, UI build/Playwright.
   Прямые live-примеры, затем те же задачи через агента без ручной правки кода.

## Приёмочные задачи

- Кронштейн: T2, Rвнутр2, наружные полки 60×40, длина 80; два Ø9 на середине
  60-мм полки, по 20 от торцов; листовой элемент, развёртка, управляющие размеры.
- Втулка: вращение, Øнаруж30/Øвнутр16×40, наружные фаски 1×45°, одно тело,
  понятные управляющие размеры.
- Сборка с валом Ø15,8×60: втулка закреплена, концентричность и совпадение торцов,
  у вала свободно только осевое вращение.
- Изменение 80→100 и Ø30→34; перестроение и сохранение сопряжений.
- Только новые документы и временные файлы. При ошибке/unknown остановиться.

## Допущения

Настроенный провайдер с native tools. Без C#, перехвата MecAgent, маршрутизации
провайдеров, embeddings и COM-памяти между запросами. Приёмка подтверждает
конкретные сценарии, а не универсальность геометрии.
