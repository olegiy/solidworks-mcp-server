# План исправления ошибок построения

**Цель:** блокировать известные неверные вызовы до CAD и уточнить подготовку и проверку кода.

**Архитектура:** небольшой модуль AST-проверки вызывается внутри существующего
STA-задания перед `_app()`. Исполнитель получает исходный скомпилированный код.

**Технологии:** Python 3.12, ast, pytest, существующий MCP/агент.

**Спецификация:** [решение](../specs/2026-10-28-construction-errors-design.md).

Ограничения: без новых зависимостей, повторов CAD, изменений пользовательских
документов и автоматического перезапуска приложения. Новые комментарии — английские.

## Задача 1: предварительная проверка

- [x] Добавить регрессии в `tests/test_com_runtime.py`: неверный Callout и индексы,
  отсутствие доступа к `_app` и частичных изменений, корректные значения,
  `GET`, динамические аргументы, синтаксическая ошибка, отсутствие ложных совпадений
  в строках и комментариях. Запустить и наблюдать ожидаемые ошибки.
- [x] Реализовать `compile_python(code: str)` и `PythonPreflightError` в
  `cadnext/python_preflight.py`, подключить к `execute_python` и `_run`.
- [x] Повторить целевые тесты до успешного результата.

## Задача 2: инструкции и диагностика

- [x] Обновить описание `execute_python`, системные инструкции и передачу
  диагностических полей исправляющей модели. Регрессией проверить доставку
  признака предварительной проверки и подсказки через настоящий агент.
- [x] Записать разбор причин, подтверждённые сигнатуры и границы защиты в
  `docs/python-inspection.md` и `docs/verification.md`.
- [x] Выполнить Python-тесты без live, ruff, ручную проверку изменённого сервера,
  `git diff --check` и обзор изменений.

Решение исполнителя: работать в текущем checkout с сохранением уже подготовленного
пользователем удаления `demo.gif`; зависимости и UI не меняются.

Проверки: первоначально 8 ожидаемых отказов preflight-регрессий, затем 26 успешных
COM-runtime тестов. Передача диагностических полей также проверена RED → GREEN.
Независимый обзор выявил Important: инструкция минимального продолжения противоречила
тому, что preflight не выполнил подготовку объектов. Исправлено с интеграционной
регрессией RED → GREEN через реальный `execute_python` на COM-подобной модели.
Самопроверкой исправлена классификация исключения `PythonPreflightError`, поднятого
внутри исполняемого пользовательского кода: оно не означает отсутствие изменений.
Minor обзора: распознавание методов по имени может задеть локальные классы;
ограничение явно задокументировано, полный вывод типов не добавляется.
