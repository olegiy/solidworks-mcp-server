# CAD-Agent-Next: новый минимальный проект

Дата: 25 октября 2026 года. Статус: проект решения для согласования.

Актуализация по последнему запросу пользователя: подтверждение отправки данных
удалено. Agent автоматически разрешает передачу текста выбранному API и снимков
при `vision`, сохраняя маскирование текста. По запросу пользователя от 26 октября
разрешение Python сохраняется постоянно для приложения, всех диалогов и подключений,
включая перезапуск; отзывается переключателем в настройках. Без него первый
фрагмент показывает точный код и предлагает «Разрешить постоянно».
Эта поправка заменяет прежние требования согласия и подтверждения каждого фрагмента
в историческом описании ниже.

## Подтверждённое направление

Пользователь хочет заново собрать небольшой, понятный проект на основе
[aiforyouself/solidworks-mcp-server](https://github.com/aiforyouself/solidworks-mcp-server),
перенося из текущего CAD-Agent только необходимое. Новый проект располагается рядом
с текущим. В первой версии нужен собственный чат с выбором модели.

Причина: накопившаяся сложность, лишние компоненты и постоянные ошибки.
Новая версия должна быть самостоятельной: её запуск и работа не зависят от файлов,
виртуального окружения, базы данных или запущенных процессов старого CAD-Agent.

## Предлагаемый результат первой версии

Одно локальное приложение: чат, настройки подключений моделей, выбор активной
модели, видимые вызовы CAD-инструментов и снимки результата из SolidWorks.
Один запрос выполняется одной выбранной моделью. Пользователь может менять
подключение между запросами; текущий запрос сохраняет исходное подключение.

Решения автора проекта документа, пока не отдельные требования пользователя:

- Рабочее имя и каталог: `C:\Users\olegiy\CAD-Agent-Next`.
- Windows, Python 3.12+, FastAPI; интерфейс React/TypeScript/Vite, как сейчас.
- Один Python-процесс приложения и один дочерний Python MCP-процесс.
- API и собранный интерфейс обслуживаются с `127.0.0.1:8876`.
- `setup.bat` устанавливает зависимости и собирает интерфейс; `start.bat`
  запускает приложение и открывает чат. Остановка завершает только свои процессы.
- Профили моделей сохраняются, переписка первой версии живёт в памяти приложения.
  Постоянная история чатов пока не входит в этот выпуск.
- Один пользователь, один активный CAD-запрос, один экземпляр SolidWorks.

## Основа и происхождение

Изучен коммит `2ad21ce7581111d55dcc85db9de32f7366d201f7` внешнего репозитория.
Он содержит один серверный файл, 27 MCP-инструментов, три прямые зависимости
(`mcp`, `pywin32`, `pillow`) и лицензию MIT. Автор проверял его на SolidWorks
2024 SP5; совместимость с нашим SolidWorks 2025 ещё предстоит проверить.
В опубликованном дереве автоматических тестов нет.

В новом репозитории сохраняются MIT-уведомление, исходный коммит и список наших
изменений. За основу берётся именно этот Python-сервер. C#-ядро не переносится.
На первом этапе сохраняется узнаваемая структура исходного сервера: без
универсальной платформы плагинов и преждевременного разбиения каждого инструмента
на отдельный модуль. Зависимости фиксируются после проверки совместимости.

## Минимальная архитектура

Поток запроса: собственный чат → Python-приложение → выбранная модель →
MCP-инструмент → SolidWorks. Результат инструмента возвращается модели перед
следующим её решением. UI получает те же события выполнения и изображения.

Приложение получает каталог из MCP `tools/list`, а не из копии каталога старого
проекта. Подключение MCP использует официальный Python SDK и stdio.
Между приложением и браузером достаточно одного потока событий на запрос.

Агентский цикл:

1. Отправить историю диалога и доступные инструменты выбранной модели.
2. Получить текст или вызовы инструментов.
3. Проверить вызовы по каталогу и выполнить их строго последовательно.
4. Передать фактические результаты с правильными `tool_call_id` в историю модели.
5. Если есть новое изображение, передать его модели с поддержкой изображений.
6. Продолжить до итогового ответа, остановки, ошибки или лимита вызовов.

Известная ошибка `execute_python` с определённым результатом `CAD_ERROR` может
запросить у модели ограниченное исправление: не более двух попыток в рамках того
же запроса. Перед исправлением модель получает диагностические поля и должна
использовать read-only инспекцию, затем выполнить только минимальное продолжение.
Исходный скрипт целиком не повторяется. Неизвестный результат COM, таймаут или
ошибка связи остаются аварийной остановкой без повторения.

Снимки для модели передаются в поддерживаемом формате сообщения с изображением,
а не маскируются под текст. Если модель не принимает изображения, UI всё равно
показывает снимок, а агент получает текстовые результаты. Автоматически выбирать
другую модель приложение не должно. Каталог и история ограничиваются по размеру;
при исчерпании контекста прогон останавливается с понятным сообщением.

Начальный лимит — 80 инструментальных вызовов на запрос, с возможностью изменить
его в настройках. Все вызовы, включая служебные проверки, учитываются в лимите.
Сложный сценарий из демонстрации автора занял 58 вызовов — лимит 20 для него мал.

## Подключения моделей и данные

Один тип подключения: OpenAI-совместимый API с настоящим `tool calling`.
Настройки: название, адрес API, модель, необязательный ключ, поддержка изображений
и признак локального подключения. Есть проверка подключения, загрузка списка
моделей и ручной ввод имени модели. Провайдер без списка моделей остаётся пригодным
при ручном указании имени. Отсутствие `tool calling` диагностируется явно.

Фиксированные роли моделей, маршрутизация, текстовый fallback для инструментов,
автоматический выбор запасного провайдера и embeddings в первую версию не входят.

Настройки хранятся в отдельном каталоге `%LOCALAPPDATA%\cad_agent_next` как JSON
с атомарной записью. Ключи — в Windows Credential Manager под новым именем сервиса
`cad_agent_next`; настройки содержат только ссылки. Старые ключи, профили и БД
автоматически не импортируются и не изменяются. Локальное подключение может
работать без ключа.

Перед отправкой CAD-данных внешнему провайдеру сохраняется явное согласие для
текущего диалога и подключения; изображения включаются отдельным разрешением.
По умолчанию локальным считается только loopback-адрес; другой локальный сервер
пользователь явно отмечает в настройках. Обработка путей и заданных пользователем
конфиденциальных строк применяется ко всем исходящим текстовым сообщениям,
включая ответы инструментов. Необработанные результаты остаются внутри сервера;
подстановка скрытых путей в последующие локальные аргументы выполняется сервером.
Текстовая обработка не объявляется обезличиванием изображения.

Диагностический журнал содержит инструмент, время, длительность и статус.
Ключи, тексты запросов, исходный исполняемый код, полные пути и изображения в него
не попадают. Подробный `calls.jsonl` внешней основы по умолчанию отключается.

## Инструменты SolidWorks

Сохраняется базовый набор внешнего сервера: подключение; документы; снимок;
дерево; масса; параметры листового металла; чтение и изменение размера;
перестроение; эскиз, прямоугольник, окружность, линия; базовая кромка;
сквозной вырез; развёртка DXF; компоненты и сопряжения сборок; `execute_python`.
Итого 27 инструментов. Это исходный набор, без требования восстановить 82 старых.

Основа специализируется на листовом металле. Обычные выдавливания, вращения,
скругления и чертежи не представлены отдельными инструментами. Python-выполнение
остаётся способом выполнить отсутствующую операцию, но не обещанием готовой
поддержки всех CAD-сценариев. Отбор новых готовых инструментов выполняется позже
по реальным задачам, после проверки основы.

`execute_python` сохраняет совместимость с исходным проектом. Перед каждым
выполнением UI показывает точный код для подтверждения. Подтверждение привязано
к конкретному ожидающему вызову; отказ не исполняет код. Приложение не называет
это изолированной песочницей. Обычные CAD-команды выполняются в рамках запроса.

## Обязательные небольшие исправления основы

- Все COM-операции остаются в единственном STA-потоке. Приём операций
  сериализован; параллельные вызовы модели не становятся параллельными COM-вызовами.
- Подключение только к уже запущенному SolidWorks. PID закрепляется на время
  жизни MCP-процесса. Автоматический запуск и переключение экземпляра исключены;
  при нескольких экземплярах первая версия просит оставить один.
- Таймаут возвращает состояние «результат неизвестен», блокирует следующие
  CAD-вызовы и останавливает прогон. Истечение ожидания не означает отмену COM.
  Пока прежний вызов не завершился, нельзя поднимать второй рабочий поток.
  Восстановление — отдельное действие пользователя после проверки SolidWorks;
  старый запрос автоматически не возобновляется.
- Ошибка CAD-инструмента останавливает текущий прогон. Автоматических повторов
  мутаций и автоматического undo нет. Каскады изменяющих API-вызовов из основы
  проверяются: второй вариант допустим только при установленном отсутствии
  побочного результата первого; иначе возвращается неопределённый исход.
- JSON `{status: "error"}` внутри MCP text считается ошибкой, даже когда
  внешнее MCP-поле `isError` отсутствует.
- Миллиметры/градусы на внешней границе, метры/радианы в COM. Чтение и запись
  углового размера не проходят через коэффициент длины, как сейчас в основе.
- Снимки используют уникальные временные файлы и удаляют их после чтения.
- Возврат успешного вызова отличается от подтверждения построения. Для изменения
  размера требуется повторное чтение, для создания элемента — проверка результата
  и дерева, для сохранения/экспорта — проверка файла. Для произвольного кода
  без независимого критерия отображается «выполнено, результат требует проверки».
  Проверку нельзя заменять только текстом итогового ответа модели.

Привязка PID и остановка после неопределённого результата остаются небольшими
правилами одного сервера. Общий межпроцессный реестр старого проекта не переносится.

## Что использовать из текущего CAD-Agent

| Материал | Что именно использовать | Что не переносить вместе с ним |
|---|---|---|
| `providers/openai_compatible.py`, `contracts/chat.py` | Проверенные фрагменты сериализации tool calls, результатов и изображений, разбора потока и ошибок | Embeddings, большие общие контракты, routing, fallback, RAG |
| `secrets/store.py`, `secrets/windows_keyring.py` | Небольшие обёртки системного хранилища, с новым namespace | Старые ключи и связанное хранилище профилей |
| `ui/src/features/chat`, `ui/src/features/providers` | Отдельные элементы ввода, выбора модели, отображения вызовов, прокрутки и обработки ошибок | Страницы целиком, общий `providerApi`, макросы, файлы, задачи, CAD-viewer |
| `agent/verification.py` и тесты ошибок | Правила проверки и полезные сценарии регрессий, адаптированные к новым именам | Старый executor, planner и каталог 82 инструментов |

Решение о копировании каждого фрагмента принимается по его импортам и тестам.
Новый пакет не импортирует `cad_agent` из старой папки. Сходная обязанность
не означает обязательный перенос старого класса.

Не включаются: .NET/SwCore/Roslyn/REPL, RAG, индекс CAD-файлов, SQLite-схема
старого продукта, база знаний, 3D-просмотрщик, генератор чертежей, фоновые задачи,
библиотека макросов, паритет с legacy-cad-app и матрица семи провайдеров.

## Проверка и последовательность выпуска

1. Проверить исходную MCP-основу на нашем Python и SolidWorks 2025: запуск,
   каталог, подключение, документы, дерево, снимок. Зафиксировать несовместимости.
2. Исправить только необходимые ошибки основы и добавить проверки этих границ.
3. Подключить модель и агентский цикл сначала без браузерного интерфейса.
4. Добавить минимальный собственный чат и настройки моделей.
5. Проверить установку и работу из новой папки при остановленном старом приложении.

Обязательные автономные проверки: результат инструмента меняет следующий запрос
модели; снимок реально передаётся vision-модели; native и вложенная JSON-ошибка
не превращаются в успех; неопределённая мутация не повторяется; остановка
не запускает следующий вызов; неподтверждённый Python-код не исполняется;
ключи не попадают в конфигурацию, ответы UI и логи. Нужен отдельный smoke-тест
настоящего stdio MCP, а не только вызовы Python-функций напрямую.

Пользовательская остановка запрещает дальнейшие шаги. Если COM уже выполняется,
UI сообщает об ожидании его результата; приложение не обещает прервать или
откатить уже начатую операцию. Разрыв браузерного соединения также запрещает
новые шаги. Повторное подключение показывает статус существующего запроса,
не создавая новую CAD-операцию.

Живой критерий первого выпуска: из чата прочитать активную модель, увидеть снимок,
по явному запросу изменить известный линейный размер и независимо прочитать
новое значение. Затем в новой детали проверить листовой кронштейн по сценарию
внешнего проекта, сохранить SLDPRT и DXF и проверить фактические размеры.
Автоматические проверки без SolidWorks и живые CAD-проверки отмечаются раздельно.

Крупные корпуса, legacy-аналитика и старые артефакты в новый репозиторий не копируются.
Разработка начинается после согласования этого состава первой версии.
