# Подключения моделей и приватность

Задача 2 реализована как Python-слой. Агентский цикл и интерфейс относятся к следующим задачам.

## Настройки

`SettingsStore()` хранит профили в `%LOCALAPPDATA%\cad_agent_next\settings.json`.
Запись выполняется через временный файл в том же каталоге, `fsync` и атомарную замену.
При ошибке замены прежние настройки остаются на диске и в памяти, изменение ключа откатывается.
JSON и Windows Credential Manager не образуют общую транзакцию при аварийном завершении процесса.

`save(values, profile_id=None)` создаёт или обновляет подключение, `get`, `list`, `delete`
читают и удаляют его. `Profile` — неизменяемый снимок: изменение сохранённого профиля
не изменяет уже полученный объект текущего запроса.

Поля: `name`, `base_url`, `model`, `vision`, `local`, `reasoning_effort`. Адрес должен быть HTTP(S),
без встроенных учётных данных, query-параметров и фрагмента.
По умолчанию локальны только `localhost` и loopback IP. LAN-сервер можно явно отметить
через `local=True`. При изменении адреса признак локальности вычисляется заново,
если новое значение `local` не передано явно.

`reasoning_effort` сохраняется в JSON вместе с подключением. Допустимы `none`,
`minimal`, `low`, `medium`, `high`, `xhigh`, `max` либо `null` (по умолчанию API).
Старые файлы без поля читаются с `null`; частичное изменение других полей сохраняет
выбранный уровень. `null` не отправляется провайдеру, остальные значения передаются
в Chat Completions без преобразований и автоматического подбора альтернатив.
Доступность зависит от конкретной модели и провайдера; форматы проверены по
[официальной справке Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

`api_key` принимается только при сохранении и записывается напрямую в
`WinVaultKeyring`, сервис `cad_agent_next`, имя записи — ID профиля.
Пропуск поля сохраняет ключ, если нормализованный адрес API не изменился;
завершающий `/` при сравнении не учитывается. При смене адреса прежний ключ удаляется,
если новый `api_key` не передан явно. Пустая строка или `None` также удаляет ключ.
При ошибке записи настроек прежний адрес и ключ сохраняются.
`public(profile)` возвращает поля профиля и `has_key`; `secret(id)` предназначен
только для внутреннего создания провайдера. Ключ не входит в JSON или `Profile`.

## Провайдер

`Provider(profile, secret=None, privacy=context)` использует `httpx.AsyncClient`.
Методы: `complete(messages, tools)`, `list_model_catalog()`, совместимый `list_models()`, `aclose()`.
`complete` возвращает сообщение assistant с текстом и/или настоящими `tool_calls`.
ID вызовов сохраняются, аргументы должны быть JSON-объектами; усечённые и некорректные
ответы останавливаются с `ProviderError`. API, отклонивший инструменты, получает явную диагностику.

Имя модели передаётся из профиля непосредственно, без обязательного запроса `/models`.
Ошибка загрузки списка не меняет выбранную модель. Автоматических повторов, переходов
на другой API и текстовой имитации инструментов нет. HTTP redirect не выполняется;
прокси из переменных окружения не используются. Ошибки содержат безопасное русское
описание и HTTP-статус, без тела ответа, ключей или исходного исключения HTTPX.

Для точного домена `openrouter.ai` `list_model_catalog()` дополнительно нормализует
поля `reasoning.mandatory`, `reasoning.default_effort` и
`reasoning.supported_efforts` из каталога OpenRouter. Разрешены только значения,
которые принимает локальная схема `ReasoningEffort`; неизвестные значения отбрасываются.
Для остальных API эти поля игнорируются. Каталог не выполняет пробных запросов модели.

Отдельный `ReasoningCatalog` получает публичный каталог OpenRouter без авторизации
для уровней рассуждения любого подключения. Запрос всегда идёт к
`https://openrouter.ai/api/v1/models`; ключи сторонних API, история чата и имя
настроенной модели не отправляются. Поиск выполняется локально: точный ID либо
уникальное совпадение имени после `/`. Неизвестные суффиксы вроде `-highspeed`
не удаляются. Неоднозначность, отсутствие модели или недоступность каталога дают
явное пояснение в UI и стандартный список. Кеш общий на час; после сетевой ошибки
повторная загрузка разрешена через 15 секунд. Поддержка этих уровней сторонним
сервером остаётся свойством его API.

## Согласие и данные

Для прогона создаётся свой `PrivacyContext` с `session_id`, `profile_id`, `local`
и `vision` из выбранного снимка профиля. При передаче контекста в `Provider` он
закрепляется за ID, адресом и моделью. Повторное использование для изменённого
подключения отклоняется: нужен новый контекст.

По запросу пользователя Agent автоматически вызывает
`context.grant(session_id=..., profile_id=..., images=profile.vision)` при старте,
без окна подтверждения передачи данных. Несовпадающие ID отклоняются.
Для изображений нужна поддержка `vision`. Текстовая модель получает
текстовое пояснение вместо сообщения, состоящего только из запрещённого изображения.

Сам `PrivacyContext` и прямое использование `Provider` вне Agent сохраняют низкоуровневую
проверку разрешений. Это не пользовательский поток приложения; в нём Agent выдаёт
разрешения автоматически, сохраняя фильтрацию внешних текстов.

`Provider.complete` самостоятельно обрабатывает исходную локальную историю и описания
инструментов. Абсолютные пути Windows/UNC/POSIX и заданные `sensitive`-строки
заменяются токенами; исходные данные не изменяются. Восстановление аргументов перед
локальным MCP-вызовом выполняется тем же `context.restore(arguments)`.
Не следует восстанавливать данные перед отправкой модели.

Роли, ID вызовов, имена функций, имена аргументов и структура JSON Schema остаются
служебными полями протокола. Фильтруются содержимое сообщений, значения аргументов,
результаты инструментов, описания и текстовые значения схем. Текстовая фильтрация
не обезличивает изображение. Блоки изображений не превращаются в текст base64.

## Проверка

Автономные тесты используют временные каталоги, тестовое хранилище секретов
и HTTPX MockTransport. Проверяются фактические HTTP-запросы, отсутствие запроса
без согласия, payload изображений, ошибки, атомарная запись и восстановление путей.
Независимый обзор выявил дополнительные пограничные случаи; они закреплены регрессиями.
Живые обращения к LLM и запись реальных ключей в Credential Manager не выполнялись.

Команда проверки пункта 2:

```powershell
.venv\Scripts\python.exe -m pytest tests/test_settings.py tests/test_provider.py tests/test_privacy.py -q
```
