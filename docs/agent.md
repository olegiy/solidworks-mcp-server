# Последовательный агентский цикл

Задача 3 реализована в `cadnext/agent.py`. Приложение, HTTP/SSE и браузерный чат
добавлены в задаче 4 (см. `app.md`). Реальные CAD-операции в задаче 3 не выполнялись.

## Использование

`Agent` получает уже подключённый `SolidWorksMcp`. Подключением MCP и временем жизни
провайдера владеет вызывающее приложение. Все методы вызываются из одного event loop.

```python
agent = Agent(mcp)
run = agent.start(session_id=session_id, provider=provider, message=user_message)
await agent.wait(run.id)
snapshot = run.snapshot()
```

`start` сразу закрепляет единственный активный запрос; второй получает `AgentBusy`.
Профиль — неизменяемый снимок внутри провайдера. История диалогов хранится в памяти
агента по `session_id`, восстановление после перезапуска приложения пока не предусмотрено.
Передача другого профиля в следующем ходе сохраняет локальную историю, но новый
провайдер заново применяет свои ограничения приватности ко всем сообщениям.

`Run` содержит `id`, `session_id`, `profile_id`, `status`, `messages`, `events`,
`stop_requested`, `confirmation`, `call_count`, `max_calls`, `checks`, `verification`.
Для API предназначен `snapshot()` — независимая копия данных без провайдера,
ключей, фоновой задачи и объектов синхронизации. Исходные тексты и локальные результаты
видны локальному интерфейсу; фильтрация применяется перед внешним HTTP-запросом.

## Модель и инструменты

Каталог извлекается через `mcp.tools()`. Имена и JSON Schema проверяются; неизвестные
инструменты, некорректные аргументы, NaN/Infinity и повторные ID вызовов останавливают
прогон до их исполнения. JSON Schema не загружает ссылки из сети.

Несколько native tool calls одного ответа выполняются последовательно. Их исходные
ID сохраняются в сообщениях `tool`. Фактический результат передаётся модели перед
следующим решением. Проверяющие вызовы вкладывают свои результаты в `verification.evidence`;
они не добавляются как неподтверждённые моделью tool calls в историю протокола.
Если пакет прерван, невыполненные вызовы получают явный ответ об остановке.

Снимки остаются image-блоками: UI получает событие `image`, история — сообщение
с `data:image/...;base64,...`. Снимки уже завершённых вызовов сохраняются и при отказе
от последующего Python-кода. Провайдер передаёт их модели только при `vision` и,
для внешнего подключения, отдельном согласии. Изображение не подменяется текстом base64.

По умолчанию разрешено 80 MCP-вызовов на запрос; `max_calls` принимает 1–1000.
Служебные чтения до/после изменений учитываются в этом же счётчике. Перед мутацией
агент проверяет наличие нужных инструментов проверки и запас вызовов на всю проверку.
Каталог ограничен 256 КиБ, исходящая история и отдельный ответ модели — 8 МиБ;
лимиты можно задать в конструкторе. Ошибка контекста завершает прогон без fallback.

## Подтверждения и остановка

Перед облачным запросом без согласия появляется `confirmation` с `kind="privacy"`.
Приложение показывает адрес подключения и отдельный выбор передачи изображений.
После ответа пользователя:

```python
agent.confirm(run.id, confirmation_id, approved=True, images=False)
```

Контекст согласия закрепляется за диалогом, профилем, адресом и моделью.
`kind="python"` содержит точный код после восстановления локальных путей.
Каждый `execute_python` требует нового подтверждения, даже при одинаковом коде.
Отказ завершает прогон со статусом `rejected`. Устаревший, чужой или повторный ID
отклоняется. Python имеет доступ к системе и COM; песочницей этот механизм не является.

`stop(run.id)` запрещает новые действия. Если COM-вызов уже отправлен, статус
становится `stopping`; агент сохраняет его фактический исход и не вызывает readback
или следующий инструмент после остановки. Выполненное изменение не откатывается.
Если текущий вызов завершается таймаутом, итог остаётся `uncertain`, даже после stop.

`await agent.wait(run.id)` защищает рабочую задачу через `asyncio.shield`:
отмена браузерного ожидания не отменяет COM. Приватную задачу Run отменять нельзя.
`await agent.aclose()` запрещает новые запросы, останавливает текущий и ждёт его исход.

## Независимая проверка

| Действие | Что проверяется |
|---|---|
| `set_dimension` | Имя, единицы и фактическое значение через `get_dimension`; допуск 0,000001 мм/градуса |
| `create_sketch`, `cut_through`, `add_mate` | Возвращённое имя отсутствует до операции и присутствует в дереве после |
| `create_base_flange` | Новый элемент дерева и фактические толщина/радиус с учётом округления MCP до четырёх знаков |
| `create_part`, `create_assembly` | Новый документ в списке открытых документов и доступное дерево |
| `add_component` | Новый компонент с нужным путём, отсутствие подавления и присутствие в дереве |
| `save_document`, `export_flat_pattern_dxf` | Правильный путь, непустой файл и изменение размера/времени файла относительно состояния до вызова |
| Эскизная геометрия, закрытие эскиза, перестроение | Чтение дерева как свидетельство; точная геометрия остаётся `unverified` |
| `execute_python` и действия без независимого критерия | «Выполнено, результат требует проверки» |

Для дерева запрашивается до 1000 элементов. Если до создания достигнут этот предел,
агент прекращает прогон до мутации: полнота исходного дерева не подтверждена.
Проверка файла подтверждает запись, но не проверяет геометрию внутри SLDPRT/DXF.
Проверка дерева подтверждает наличие элемента, но не все его инженерные свойства.

`status="completed"` означает завершение цикла. Достоверность мутаций отражается
отдельно: `verification` принимает `not_required`, `verified`, `unverified`, `failed`.
Любое непроверенное действие сохраняет `unverified` у всего прогона. Модельный текст
не изменяет серверную отметку проверки. Ошибка readback сохраняется в истории
вместе с фактическим значением; повтор мутации не выполняется.

CAD-ошибка, включая вложенный `{status: "error"}`, завершает прогон. Потеря MCP,
повреждённый ответ и COM-таймаут сохраняют неопределённый исход и блокируют новые
запросы до перезапуска. Автоматических повторов, undo или смены исполнителя нет.

## События для интерфейса

`agent.events(run.id, after=seq)` — асинхронный генератор событий с полями
`seq`, `type`, `data`. Поддерживаются `message`, `tool_start`, `tool_result`,
`image`, `confirmation`, `status`, `error`. Номера начинаются с 1.
Снимок и получение пропущенных событий не выполняют CAD-инструменты заново.
Медленный потребитель получает и события, добавленные во время его паузы.
Закрытие генератора активного прогона вызывает `stop`.

У мутации сначала появляется фактический `tool_result`, затем обновлённый результат
с независимой проверкой; интерфейсу следует обновлять запись по `tool_call_id`.
Проверяющие операции помечены `verification=True` и имеют собственные ID.
После завершения используются статусы `completed`, `stopped`, `failed`, `uncertain`,
`limit_reached`, `rejected`; во время работы — `queued`, `running`,
`awaiting_confirmation`, `stopping`.

Диагностический logger `cadnext.agent` пишет имя инструмента, длительность и статус.
Запросы, код, полные пути, ключи и изображения в диагностику не записываются.

## Проверка

```powershell
.venv\Scripts\python.exe -m pytest tests/test_agent.py -q
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
```

67 сценариев агента проверяют последовательность, результаты, подтверждения,
приватность через настоящий `Provider` с HTTPX MockTransport, остановку и лимиты.
Отдельный тест использует настоящий stdio MCP и его каталог без CAD-мутаций.
Независимый обзор выявил потерю завершающих событий, округление листовых параметров,
усечение дерева и потерю снимков при прерывании пакета; исправления проверены регрессиями.
Живой SolidWorks и живой LLM-провайдер для этого пункта не проверялись.
