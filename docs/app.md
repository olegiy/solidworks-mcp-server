# Локальное приложение и чат

Пункт 4 добавляет FastAPI API и React/TypeScript-чат. Приложение обслуживает API и
собранный интерфейс с одного адреса `http://127.0.0.1:8876`. Оно владеет одним
MCP-подпроцессом и одним последовательным агентом; одновременно выполняется один прогон.

## Ручной запуск

Из корня репозитория, с уже установленными Python-зависимостями:

```powershell
Push-Location ui
npm ci
npm run build
Pop-Location
$env:PYTHONUTF8=1
.venv\Scripts\python.exe -m cadnext
```

Открыть `http://127.0.0.1:8876` вручную. SolidWorks должен быть запущен для CAD-вызовов;
приложение не запускает его автоматически. Ctrl+C завершает приложение и MCP после
исхода начатой операции. Порт резервируется до запуска MCP: второй ручной экземпляр
получает сообщение о занятом порте. Скрипты setup/start/stop добавлены в пункте 5:
обычный start запускает фоновой экземпляр, повторный использует тот же, stop подаёт
управляющий сигнал и ждёт агента/MCP. Ручной экземпляр остаётся под управлением Ctrl+C.

Кнопка «Настройки» в шапке открывает подключения, надпись «На этом компьютере» и
параметр «Лимит вызовов». Лимит вынесен из формы сообщения в параметры запросов
внутри настроек; изменение действует для следующего запроса.

В настройках можно создать, изменить и удалить подключение, ввести модель вручную,
выбрать её из списка API и проверить native tool calling. При открытии поля «Имя
модели» список загружается автоматически, в том числе для ещё не сохранённого
подключения. Ввод фильтрует названия без учёта регистра и без новых сетевых запросов.
Выбор доступен мышью или стрелками ↑/↓ и Enter; Escape закрывает список. Для открытия
списка оставлена одна кнопка со стрелкой справа от поля. После ошибки повторное
открытие загружает каталог заново. При пустом каталоге остаётся ручной ввод.
Смена адреса, ключа или подключения сбрасывает список и отменяет старый запрос.
Загрузка использует текущий адрес и введённый ключ без сохранения настроек; сохранённый
ключ подставляется только для прежнего адреса API. Проверка подключения отправляет только
фиксированное сообщение и фиктивный инструмент, без истории CAD. Сохранённый ключ API
хранится в Windows Credential Manager; пустое поле сохраняет прежний ключ, отдельный
флажок удаляет его. В localStorage сохраняются только ID диалога и подключения.

Поле «Сила рассуждения» для всех подключений получает список `reasoning.supported_efforts`
выбранной модели из публичного каталога OpenRouter и показывает только эти значения; при обязательном
рассуждении скрывается «Без рассуждения», выбирается рекомендованный уровень
(либо первый допустимый). Если каталог не публикует уровни обязательного рассуждения,
остаётся «По умолчанию API»: приложение не придумывает значения. Старый несовместимый
выбор нормализуется при сохранении и перед следующим запросом. Совпадение ищется по полному
ID либо уникальному имени без префикса поставщика. Суффиксы и псевдонимы не угадываются.
При отсутствии однозначного совпадения или ошибке каталога остаётся стандартный список: режим API по умолчанию и значения
«Без рассуждения», «Минимальная», «Низкая», «Средняя», «Высокая», «Очень высокая»,
«Максимальная».
Под полем указаны источник уровней или причина стандартного списка. Кнопка «Обновить уровни»
повторяет локальную загрузку; публичный каталог кешируется сервером на час, ошибки — на 15 секунд.
Ключи подключений и история не передаются в OpenRouter. Уровни OpenRouter описывают модель;
совместимость конкретного стороннего API с параметром зависит от этого API.
После «Сохранить подключение» выбор остаётся при повторном входе и перезапуске
приложения. Старые подключения открываются с режимом API по умолчанию. Уровень
передаётся как `reasoning_effort` в Chat Completions, включая проверку подключения;
режим по умолчанию не добавляет параметр. Поддерживаемые значения зависят от модели/API.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/health` | Доступность, активный прогон, флаг неизвестного исхода |
| `GET/PUT /api/settings` | Общее постоянное разрешение `python_execution_allowed` (bool), без ключей и профилей |
| `GET/POST /api/profiles` | Список / создание подключения |
| `GET/PUT/DELETE /api/profiles/{id}` | Чтение / изменение / удаление подключения |
| `GET /api/models?profile_id=...` | Каталог выбранного API: `{models:[{id,reasoning}]}` |
| `GET /api/reasoning?model=...` | Уровни из публичного OpenRouter: `{status,model_id,reasoning}`; без ключей подключения |
| `POST /api/models` | Каталог текущей формы без сохранения: `base_url`, необязательные `profile_id`, `api_key`; ключ не возвращается |
| `POST /api/profiles/{id}/test` | Проверка подключения и native tools без CAD |
| `POST /api/runs` | Запуск, HTTP 202 и снимок состояния |
| `GET /api/runs?session_id=...` | Снимки прогонов диалога |
| `GET /api/runs/{id}` | Текущее состояние без повторного исполнения |
| `GET /api/runs/{id}/events?after=N` | SSE: пропущенные и новые события |
| `POST /api/runs/{id}/stop` | Запрет следующих шагов |
| `POST /api/runs/{id}/confirm` | Решение по текущему уникальному ID подтверждения |
| `POST /api/requests/{request_id}/stop` | Остановка даже до получения браузером ID прогона |

`POST /api/runs` принимает `session_id`, `profile_id`, `message`, необязательные
`max_calls` (по умолчанию 80, от 1 до 1000), `sensitive` (строки для фильтрации)
и `request_id`. Чат генерирует новый `request_id` до отправки POST. Повторный ID
получает 409; заранее полученный stop блокирует запуск с этим ID. Это закрывает гонку
между закрытием вкладки и доставкой ответа о запуске.

Подтверждение Python принимает `confirmation_id` и `approved`. Поле `images` сохраняется
в API для совместимости и не управляет текущей политикой передачи данных.
Чужое/устаревшее подтверждение возвращает 409. Профиль закрепляется одним
неизменяемым снимком при старте; его редактирование не меняет текущий прогон.
Первое разрешение Python сохраняется постоянно для всех диалогов и подключений,
включая перезапуск приложения. Переключатель «Всегда разрешать выполнение Python»
в настройках позволяет включить или отозвать его и сохраняется сразу. При отзыве
текущий выполняющийся код не отменяется, следующий фрагмент потребует разрешения.
Подтверждения передачи данных удалены; изображения
передаются только при включённой поддержке изображений выбранного подключения.

SSE выдаёт `event: update`, `id: <seq>` и JSON `{seq,type,data}`. `Last-Event-ID`
имеет приоритет над `after`; недопустимый номер возвращает 422. Разрыв потока
вызывает stop, но не отменяет начатый COM-вызов. Чат также отправляет stop через
beacon при закрытии/обновлении страницы. После обновления он читает существующие
снимки, подключает SSE и контрольный опрос; новый CAD-запрос не создаётся.

Чат показывает сообщения, изображения, фактические вызовы/результаты в журнале,
статус остановки и отдельный результат проверки. Успешно исполненный произвольный
код остаётся «Результат требует проверки». Первое подтверждение показывает код
и явно сообщает область постоянного разрешения и возможность отозвать его в настройках.

Снимок SolidWorks всегда центрирует и вписывает текущий вид в окно перед захватом.
Ориентация сохраняется, кроме явно запрошенной изометрии. Захватывается весь вид;
PNG пропорционально уменьшается до заданных width/height без обрезки.

Лента оформлена как переписка: сообщения пользователя находятся справа в голубых
пузырях, ответы модели — слева в светло-серых. Поле ввода остаётся внизу окна,
прокручивается сама переписка. Enter отправляет сообщение, Shift+Enter добавляет
новую строку; во время выполнения доступна кнопка остановки. Подсказки на стартовом
экране только заполняют поле ввода и сами не запускают CAD.

Ответы модели поддерживают Markdown: списки, выделение, таблицы и блоки кода.
Кнопки копирования сохраняют исходный Markdown ответа или текст отдельного блока.
HTML не исполняется; внешние картинки из Markdown не загружаются. Снимки SolidWorks
по-прежнему поступают только из фактических событий CAD. Настройки открываются
отдельным окном с клавиатурной навигацией и закрытием по Escape.

Выбор сохранённого подключения и модели расположен в шапке рядом с названием
приложения. Кнопка копирования ответа находится в строке автора. Развёрнутый журнал
занимает область примерно на пять операций и открывается на последних записях;
предыдущие операции и ошибки доступны прокруткой. При ручной прокрутке вверх новые
события не возвращают пользователя вниз автоматически.

«Поддержка изображений» в настройках разрешает передавать модели снимки,
полученные из SolidWorks. Загрузки пользовательских файлов изображений в чате нет.
Надпись «Принимает изображения» из шапки удалена, чтобы не подразумевать загрузчик.

История и согласия живут в памяти приложения. Обновление страницы их сохраняет,
перезапуск Python-приложения очищает. Ключи API не входят в снимки/ответы; ошибки
валидации не отражают тело запроса, внутренние исключения скрыты. Чужие Host/Origin
блокируются, внешние ресурсы интерфейса ограничены CSP.

## Автономная проверка

```powershell
.venv\Scripts\python.exe -m pytest tests/test_app.py -q
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
Push-Location ui
npm run build
npx playwright test
Pop-Location
```

Playwright использует `tests/web_fixture.py`: настоящий API, агент и провайдер,
фиктивные HTTP-ответы LLM и CAD. Сервер слушает 8877 и использует временные настройки
и память вместо Credential Manager. Проверяются настройки, 62 мм, снимок, согласия,
точный код/отказ, остановка, закрытие вкладки, медленные ответы, восстановление и
ширина 390 px. Это не проверка живого SolidWorks или LLM.

Для браузерных тестов нужен Chromium: при отсутствии выполнить
`npx playwright install chromium` в `ui/`. Версии npm-зависимостей закреплены в
`ui/package-lock.json`. Известное предупреждение Starlette TestClient об устаревшем
адаптере httpx не влияет на прохождение Python-тестов; зависимости Python сохранены.
