# Локальное приложение и чат

Список этапов, событие `construction_plan`, восстановление snapshot и новые поля
sidecar описаны в [staged-construction.md](staged-construction.md).

Пункт 4 добавляет FastAPI API и React/TypeScript-чат. Приложение обслуживает API и
собранный интерфейс с одного адреса `http://127.0.0.1:8876`. Оно владеет одним
MCP-подпроцессом и одним последовательным агентом; одновременно выполняется один прогон.

## Ручной запуск

Из корня репозитория, с уже установленными Python-зависимостями:

```powershell
Push-Location ui
npm ci
npm run build
Pop-Location
$env:PYTHONUTF8=1
.venv\Scripts\python.exe -m cadnext
```

Открыть `http://127.0.0.1:8876` вручную. SolidWorks должен быть запущен для CAD-вызовов;
приложение не запускает его автоматически. Ctrl+C завершает приложение и MCP после
исхода начатой операции. Порт резервируется до запуска MCP: второй ручной экземпляр
получает сообщение о занятом порте. Скрипты setup/start/stop добавлены в пункте 5:
обычный start запускает фоновой экземпляр, повторный использует тот же, stop подаёт
управляющий сигнал и ждёт агента/MCP. Ручной экземпляр остаётся под управлением Ctrl+C.

Кнопка «Настройки» в шапке открывает подключения, надпись «На этом компьютере» и
параметр «Лимит вызовов». Лимит вынесен из формы сообщения в параметры запросов
внутри настроек; изменение действует для следующего запроса.
Параметры «Оценка результата» также находятся только в настройках; порог и лимиты
сохраняются в браузере и применяются к следующему запросу.

## История проекта

«Новый проект» и «Закрыть проект» завершают текущую историю. Сервер ждёт исход
начатой операции, удаляет только этот проект и отклоняет продолжения со старым ID.
Кнопки доступны между запросами. При ошибке закрытия история остаётся на экране.
Закрытие вкладки завершает её проект: новая вкладка получает новый ID.
Обновление страницы сохраняет ID в `sessionStorage`, все сообщения, чертежи,
события и результаты проверок. Во время активного запроса обновление по-прежнему
останавливает следующие действия и ждёт отправленный COM, сохраняя историю.
История другого активного проекта к новой вкладке не присоединяется.

Между запросами чат раз в три секунды проверяет наличие связанного документа
через `list_open_documents`. Закрытие этого документа в SolidWorks завершает
проект; переключение активной детали при открытом исходном документе сохраняет
историю. Проверка сериализована с запуском, сохранением и открытием проекта;
ошибка CAD не очищает историю, неизвестный исход сохраняет блокировку до перезапуска.
Загруженная из sidecar история сначала ждёт появления своего документа в CAD,
поэтому её можно прочитать до открытия детали. После наблюдения документа
действует обычная проверка закрытия.

История хранится в памяти приложения. Для переноса между перезапусками используйте
сохранение и открытие `.cadnext.json`; обновление страницы перезапуска не требует.

## Режим отладки

В «Настройки → Диагностика» находится переключатель «Режим отладки». По умолчанию
он выключен; изменение сразу атомарно сохраняется в `settings.json` как
`debug_logging_enabled` и действует без перезапуска. При ошибке записи остаётся
прежнее состояние. В настройках показаны путь журнала, ошибка его записи, если она
есть, и ссылка «Скачать журнал отладки».

Журнал `%LOCALAPPDATA%\cad_agent_next\logs\debug.jsonl` содержит JSON по одной записи
на строку: время UTC, ID HTTP-запроса, проекта и прогона, native tool ID, события
агента, аргументы/результаты всех MCP-вызовов (включая сохранение и проверку документа),
время вызовов, исходящие запросы и ответы модели, метрики и ошибки HTTP/JSON.
Исключения содержат тип, сообщение и стек с файлом, функцией и номером строки.
Ошибки COM дополнительно возвращают `error_type` и `diagnostic_frames`; исходный
текст строк и локальные переменные в стек не включаются. Каталог MCP, правила STA,
бюджет, отмена и отсутствие повторов не меняются.

При включении записывается снимок последних 50 событий и 10 сообщений каждого
имеющегося прогона. Затем новые события пишутся по мере выполнения. Журнал живёт
отдельно от истории: закрытие проекта его не удаляет. Выключение немедленно
прекращает новые записи, прежние файлы остаются доступными для скачивания.

Запись ограничена 256 КиБ, отдельная строка текста — 32768 символами, список —
200 элементами; усечение явно помечается. Это относится только к диагностике,
полная история проекта сохраняется по прежним правилам. Ротация: текущий файл и
три предыдущих, примерно по 5 МиБ каждый. `GET /api/debug/logs` скачивает их в
`cadnext-debug.zip`, без других журналов и файлов настроек. Ошибка диска не меняет
исход CAD-операции, не вызывает повторов и отражается в настройках.

В журнале есть локальные тексты переписки, код и пути файлов. API-ключи, известные
приложению, заголовки авторизации и изображения маскируются до записи. Подробнее —
[models-and-privacy.md](models-and-privacy.md).

## Язык интерфейса

Интерфейс двуязычный: русский и английский. Переключатель языка находится в шапке
рядом с кнопками диалога и настроек. При первом запуске язык выбирается по языку
браузера (`navigator.language`): русский для `ru-*`, иначе английский. Выбор
сохраняется в `localStorage` (`cadnext.v1.language`), применяется сразу ко всем
подписям, подсказкам, статусам, журналу и ошибкам, а также обновляет `<html lang>`
и заголовок вкладки. Существующие диалоги не переводятся: сообщения модели остаются
на языке, на котором они были получены.

Выбранный язык передаётся каждому запросу в заголовке `Accept-Language`, а запуск
CAD-прогона закрепляет его полем `language` (`ru` или `en`). Ошибки API, сообщения
статусов, проверок и подтверждений локализуются на сервере; системная инструкция
агента требует отвечать на выбранном языке. При смене языка посреди диалога
следующий ответ модели выходит на новом языке, а уже показанная история не меняется.

В настройках можно создать, изменить и удалить подключение, ввести модель вручную,
выбрать её из списка API и проверить native tool calling. При открытии поля «Имя
модели» список загружается автоматически, в том числе для ещё не сохранённого
подключения. Ввод фильтрует названия без учёта регистра и без новых сетевых запросов.
Выбор доступен мышью или стрелками ↑/↓ и Enter; Escape закрывает список. Для открытия
списка оставлена одна кнопка со стрелкой справа от поля. После ошибки повторное
открытие загружает каталог заново. При пустом каталоге остаётся ручной ввод.
Смена адреса, ключа или подключения сбрасывает список и отменяет старый запрос.
Загрузка использует текущий адрес и введённый ключ без сохранения настроек; сохранённый
ключ подставляется только для прежнего адреса API. Проверка подключения отправляет только
фиксированное сообщение и фиктивный инструмент, без истории CAD. Сохранённый ключ API
хранится в Windows Credential Manager; пустое поле сохраняет прежний ключ, отдельный
флажок удаляет его. ID проекта хранится в `sessionStorage`; ID подключения,
язык и параметры оценки — в `localStorage`. Ключи там не сохраняются.

Поле «Сила рассуждения» для всех подключений получает список `reasoning.supported_efforts`
выбранной модели из публичного каталога OpenRouter и показывает только эти значения; при обязательном
рассуждении скрывается «Без рассуждения», выбирается рекомендованный уровень
(либо первый допустимый). Если каталог не публикует уровни обязательного рассуждения,
остаётся «По умолчанию API»: приложение не придумывает значения. Старый несовместимый
выбор нормализуется при сохранении и перед следующим запросом. Совпадение ищется по полному
ID либо уникальному имени без префикса поставщика. Суффиксы и псевдонимы не угадываются.
При отсутствии однозначного совпадения или ошибке каталога остаётся стандартный список: режим API по умолчанию и значения
«Без рассуждения», «Минимальная», «Низкая», «Средняя», «Высокая», «Очень высокая»,
«Максимальная».
Под полем указаны источник уровней или причина стандартного списка. Кнопка «Обновить уровни»
повторяет локальную загрузку; публичный каталог кешируется сервером на час, ошибки — на 15 секунд.
Ключи подключений и история не передаются в OpenRouter. Уровни OpenRouter описывают модель;
совместимость конкретного стороннего API с параметром зависит от этого API.
После «Сохранить подключение» выбор остаётся при повторном входе и перезапуске
приложения. Старые подключения открываются с режимом API по умолчанию. Уровень
передаётся как `reasoning_effort` в Chat Completions, включая проверку подключения;
режим по умолчанию не добавляет параметр. Поддерживаемые значения зависят от модели/API.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/health` | Доступность, активный прогон, флаг неизвестного исхода |
| `GET/PUT /api/settings` | `python_execution_allowed`, `debug_logging_enabled` (bool), Vision-маршрутизация; GET также возвращает путь, доступность и ошибку журнала; без ключей |
| `GET /api/debug/logs` | ZIP с локальным журналом отладки и его ротациями; 404 до создания журнала |
| `GET/POST /api/profiles` | Список / создание подключения |
| `GET/PUT/DELETE /api/profiles/{id}` | Чтение / изменение / удаление подключения |
| `GET /api/models?profile_id=...` | Каталог выбранного API: `{models:[{id,reasoning}]}` |
| `GET /api/reasoning?model=...` | Уровни из публичного OpenRouter: `{status,model_id,reasoning}`; без ключей подключения |
| `POST /api/models` | Каталог текущей формы без сохранения: `base_url`, необязательные `profile_id`, `api_key`; ключ не возвращается |
| `POST /api/profiles/{id}/test` | Проверка подключения и native tools без CAD |
| `POST /api/runs` | Запуск, HTTP 202 и снимок состояния |
| `POST /api/cad/save` | Сохранение активного документа и переписки без нового прогона |
| `POST /api/conversations/open` | Загрузка сохранённой переписки из файла `.cadnext.json` |
| `POST /api/projects/{session_id}/close` | Завершение проекта после исхода начатой операции, HTTP 204 |
| `GET /api/projects/{session_id}/state` | `{closed: bool}`; проверка закрытия связанного CAD-документа только при свободном агенте |
| `GET /api/runs?session_id=...` | Снимки прогонов диалога |
| `GET /api/runs/{id}` | Текущее состояние без повторного исполнения |
| `GET /api/runs/{id}/events?after=N` | SSE: пропущенные и новые события |
| `POST /api/runs/{id}/stop` | Запрет следующих шагов |
| `POST /api/runs/{id}/confirm` | Решение по текущему уникальному ID подтверждения |
| `POST /api/requests/{request_id}/stop` | Остановка даже до получения браузером ID прогона |

События `update` дополнительно содержат компактный `state`: статус, счётчики,
подтверждение, отметку проверки и метрики. UI применяет их по `seq` без чтения всей
истории. `heartbeat` раз в 2 секунды не имеет ID и подтверждает связь. Snapshot
сохраняется для открытия/восстановления; gap/разрыв не повторяет CAD. Подробности
метрик и экспериментов — [performance.md](performance.md).

`POST /api/runs` принимает `session_id`, `profile_id`, `message`, необязательные
`max_calls` (по умолчанию 80, от 1 до 1000), `sensitive` (строки для фильтрации),
`language` (`ru` или `en`), `request_id` и `evaluation` — параметры цикла цели
(`enabled`, `target_similarity`, `max_evaluations`, `max_no_progress`). Язык запуска закрепляется за прогоном и
определяет системную инструкцию агента и тексты событий; без него используется
`Accept-Language` запроса. Чат генерирует новый `request_id` до отправки POST.
Повторный ID получает 409; заранее полученный stop блокирует запуск с этим ID.
Это закрывает гонку между закрытием вкладки и доставкой ответа о запуске.

`POST /api/cad/save` принимает `session_id` и возвращает `{ok: true, saved,
conversation?}`; `conversation` — путь записанного sidecar, а `warning` сообщает,
если CAD сохранён, но переписку записать не удалось. Пока идёт прогон или другое
сохранение, при отсутствии активного документа и при неизвестном исходе API
отвечает 409; ошибка CAD — 422. Неизвестный исход также блокирует новые прогоны до
перезапуска.

`POST /api/conversations/open` принимает `{conversation: <JSON sidecar>}`,
проверяет схему, версию, размер, сообщения, события и завершённость прогонов и
возвращает `session_id`, `profile_id`, `language`, `document` и снимки прогонов.
Загруженные прогоны регистрируются в памяти, поэтому переживают обновление
страницы; исходный JSON остаётся на диске.

Подтверждение Python принимает `confirmation_id` и `approved`. Поле `images` сохраняется
в API для совместимости и не управляет текущей политикой передачи данных.
Чужое/устаревшее подтверждение возвращает 409. Профиль закрепляется одним
неизменяемым снимком при старте; его редактирование не меняет текущий прогон.
Первое разрешение Python сохраняется постоянно для всех диалогов и подключений,
включая перезапуск приложения. Переключатель «Всегда разрешать выполнение Python»
в настройках позволяет включить или отозвать его и сохраняется сразу. При отзыве
текущий выполняющийся код не отменяется, следующий фрагмент потребует разрешения.
Подтверждения передачи данных удалены; изображения
передаются только при включённой поддержке изображений выбранного подключения.

SSE выдаёт `event: update`, `id: <seq>` и JSON `{seq,type,data}`. `Last-Event-ID`
имеет приоритет над `after`; недопустимый номер возвращает 422. Разрыв потока
вызывает stop, но не отменяет начатый COM-вызов. Чат также отправляет stop через
beacon при закрытии/обновлении страницы. После обновления он читает существующие
снимки, подключает SSE и контрольный опрос; новый CAD-запрос не создаётся.

Чат показывает сообщения, изображения, фактические вызовы/результаты в журнале,
статус остановки и отдельный результат проверки. Успешно исполненный произвольный
код остаётся «Результат требует проверки». Первое подтверждение показывает код
и явно сообщает область постоянного разрешения и возможность отозвать его в настройках.

Кнопка «Сохранить проект» находится в шапке рядом с «Открыть» и становится
доступной после завершения последнего прогона. Она вызывает `POST /api/cad/save`:
если активный документ уже
имеет путь, сохранение идёт на месте; иначе выбирается путь в «Документах» с
расширением по типу документа (`.sldprt`, `.sldasm`, `.slddrw`), а при совпадении
имени добавляется числовой суффикс. Рядом с документом записывается sidecar
`<имя>.cadnext.json` с полной историей сообщений, событиями прогонов, языком,
профилем и путём документа. Результат показывается строкой
«Сохранено: <путь> · Переписка: <файл>». Сохранение не создаёт новый Run и не
расходует лимит вызовов.

Кнопка «Открыть» в шапке принимает такой sidecar и восстанавливает переписку:
сообщения, снимки, журнал и статусы снова видны, а следующее сообщение продолжает
ту же историю с полным контекстом. Если диалог с таким ID уже есть в памяти,
загруженная копия получает новый ID. Загруженный документ нужно открыть в
SolidWorks, чтобы агент продолжил работу с ним. Sidecar ограничен 64 МиБ; битый
или незавершённый файл отклоняется с локализованной ошибкой. Переписка не
загружается автоматически при старте приложения — её выбирают кнопкой «Открыть».

## Цикл оценки цели

Параметры `evaluation` по умолчанию: `enabled=true`, `target_similarity=100`,
`max_evaluations=10`, `max_no_progress=3`. Отключение возвращает прежний режим без
зафиксированного контракта и карточки цели. `max_calls` остаётся общим бюджетом и
включает проверочные чтения.

`GET /api/settings` возвращает `vision_profile_id`, `vision_routing_approved` и
`vision_routing_fingerprint`; `PUT` принимает те же поля и `python_execution_allowed`
как частичное обновление. Назначить можно только сохранённый профиль с
`vision=true` и при явном `vision_routing_approved=true`; отзыв согласия
атомарно снимает назначение, а ошибка записи оставляет прежнее состояние.
Отпечаток включает ID, адрес, модель, `vision` и `local`; переименование профиля
назначение не сбрасывает, смена адреса/модели/локальности или удаление профиля —
сбрасывает.

Перед `Agent.start` маршрутизация выполняется один раз: если цикл включён, а
выбранный профиль не поддерживает изображения, сервер берёт назначенный
Vision-профиль; если назначения нет, возвращается 422 без запросов к модели и MCP.
При включённом цикле и уже выбранном Vision-профиле переключения нет. Один
неизменяемый профиль и один `PrivacyContext` используются и основным прогоном, и
оценочным запросом. `requested_profile_id` и фактический `profile_id` видны в
snapshot и событии `profile_selected` (`routed=true/false`).

События цели: `goal_defined`, `goal_bindings`, `goal_revision`, `goal_evaluation`,
`goal_correction`, `goal_finished`, а также `profile_selected`. `goal_defined`
передаёт зафиксированный контракт (до 64 требований), `goal_evaluation` — компактные
факты по требованиям, `goal_finished` — итог и причину; полная история оценок и
evidence доступны в snapshot (`goal`) и не дублируются в каждом событии. Повторное
подключение через `Last-Event-ID`/`after` не выполняет CAD-инструменты заново.

Sidecar сохраняет `schema="cadnext.conversation"` и `version=1`; в каждом снимке
прогона необязателен `goal.version=1`. Старые файлы без `goal` читаются как
исторические: процент не вычисляется и не синтезируется. Неизвестная версия
`goal`, несогласованный `contract_digest`, ложный `achieved` и выход за границы
лимитов отклоняются. Загрузка переписки не переоценивает результат и не
возобновляет CAD: следующий прогон заново читает документ и не считает старую
ревизию текущей. Лимиты sidecar прежние: 64 МиБ, 1000 прогонов, 100000 событий,
описание требования/обоснование до 2000 символов; изображения хранятся как ссылки
в событиях, а не дублируются в каждом событии.

Интерфейс показывает компактные параметры цикла в настройках (switch, порог,
лимиты), выбранный и эффективный профиль, а в чате — карточку с
зафиксированными требованиями, стадиями, номером оценки, фактическими и
ожидаемыми значениями, статусами и источником каждого подтверждения, остатком
бюджета и причиной остановки. Для `authority=mixed|vision` всегда выводится
предупреждение о модельной оценке. «Цель достигнута» показывается только по
серверному `outcome=achieved`; `clarification_required` — «Нужно уточнение»,
`unknown` — «Результат не удалось проверить», лимиты — «Цель не достигнута: …».
Исторический и справочный прогон показываются без процента. Вложения при
non-Vision профиле разрешены, только если существует согласованное effective
Vision-подключение; окончательно это проверяет сервер.

Снимок SolidWorks всегда центрирует и вписывает текущий вид в окно перед захватом.
Ориентация сохраняется, кроме явно запрошенной изометрии. Захватывается весь вид;
PNG пропорционально уменьшается до заданных width/height без обрезки; размер по
умолчанию — 400×300, а отображение в чате ограничено высотой 300 px.

Лента оформлена как переписка: сообщения пользователя находятся справа в голубых
пузырях, ответы модели — слева в светло-серых. Поле ввода остаётся внизу окна,
прокручивается сама переписка. Enter отправляет сообщение, Shift+Enter добавляет
новую строку; во время выполнения доступна кнопка остановки. Подсказки на стартовом
экране только заполняют поле ввода и сами не запускают CAD.

Ответы модели поддерживают Markdown: списки, выделение, таблицы и блоки кода.
Кнопки копирования сохраняют исходный Markdown ответа или текст отдельного блока.
HTML не исполняется; внешние картинки из Markdown не загружаются. Снимки SolidWorks
по-прежнему поступают только из фактических событий CAD. Настройки открываются
отдельным окном с клавиатурной навигацией и закрытием по Escape.

Выбор сохранённого подключения, модели и силы рассуждения расположен в нижней
панели рядом с кнопкой отправки; меню выбора компактные и прижаты к Send.
Кнопки копирования ответа и сообщения пользователя находятся в строке автора.
В настройках ключ API расположен сразу под адресом API, а сам диалог сделан
компактнее. Развёрнутый журнал
занимает область примерно на пять операций и открывается на последних записях;
предыдущие операции и ошибки доступны прокруткой. При ручной прокрутке вверх новые
события не возвращают пользователя вниз автоматически.

«Поддержка изображений» в настройках разрешает передавать модели снимки,
полученные из SolidWorks, и пользовательские PNG/JPEG/WebP, приложенные скрепкой
в поле ввода. Надпись «Принимает изображения» из шапки удалена, чтобы не
подразумевать отдельный загрузчик.

История и согласия живут в памяти приложения. Обновление страницы их сохраняет;
перезапуск Python-приложения очищает незасохранённую историю. Сохранённые кнопкой
Save переписки остаются в sidecar рядом с документом и загружаются кнопкой
«Открыть». Ключи API не входят в снимки/ответы; ошибки
валидации не отражают тело запроса, внутренние исключения скрыты. Чужие Host/Origin
блокируются, внешние ресурсы интерфейса ограничены CSP.

## Автономная проверка

```powershell
.venv\Scripts\python.exe -m pytest tests/test_app.py -q
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
Push-Location ui
npm run build
npx playwright test
Pop-Location
```

Playwright использует `tests/web_fixture.py`: настоящий API, агент и провайдер,
фиктивные HTTP-ответы LLM и CAD. Сервер слушает 8877 и использует временные настройки
и память вместо Credential Manager. Проверяются настройки, 62 мм, снимок, согласия,
точный код/отказ, остановка, закрытие вкладки, медленные ответы, восстановление и
ширина 390 px. Это не проверка живого SolidWorks или LLM.

Для браузерных тестов нужен Chromium: при отсутствии выполнить
`npx playwright install chromium` в `ui/`. Версии npm-зависимостей закреплены в
`ui/package-lock.json`. Известное предупреждение Starlette TestClient об устаревшем
адаптере httpx не влияет на прохождение Python-тестов; зависимости Python сохранены.
