# Чтение габаритов тела и точек эскиза

В агентском Run Python-переменные теперь сохраняются между этапами; прямой вызов
без сессии по-прежнему независим. Размеры добавляются внутри `with DIMENSIONS():`
для отключения модального ввода. Подробности — [staged-construction.md](staged-construction.md).

Ошибка `GetBodies2.GetBoundingBox` в присланном коде вызвана неверным именем метода
тела. Для `IBody2` нужен `GetBodyBox`, возвращающий шесть чисел в метрах:
`[xmin, ymin, zmin, xmax, ymax, zmax]`. Это приблизительный ограничивающий ящик,
который может меняться после перестроения; он не доказывает точные размеры детали.

В этом же фрагменте были ещё две ошибки: `GetStartPoint2`/`GetEndPoint2` возвращают
объекты `ISketchPoint`, поэтому координаты читаются через `X`, `Y`, `Z`; имя эскиза
читается у `feature.Name`, а не у `sketch.GetName()`.
У `ISketch` также нет `GetFeature`: найди `IFeature` нужного эскиза обходом
`FirstFeature`/`GetNextFeature` по заранее прочитанному имени, затем получи
`ISketch` через `GetSpecificFeature2`. Создавать ещё один эскиз для этого не нужно.

В `execute_python` уже доступен `GET(obj, name, *args)`: он учитывает, что pywin32
может представить COM-метод как свойство. Минимальные исправления:

```python
box_mm = [v * 1000 for v in GET(body, "GetBodyBox")]
start = GET(line, "GetStartPoint2")
start_mm = [start.X * 1000, start.Y * 1000, start.Z * 1000]
sketch_name = feature.Name
```

Ошибка `'bool' object is not callable` в присланном коде воспроизводится на
`model.EditRebuild3()`: в этой связке pywin32 перестроение выполняется уже при
чтении атрибута, возвращает `bool`, после чего скобки пытаются вызвать этот
результат. Для COM-членов без аргументов используй `GET`, в частности:

```python
if not GET(model, "EditRebuild3"):
    raise RuntimeError("Перестроение завершилось с ошибками.")
```

Это изменяющий вызов, а не проверка только чтения. Код, который до него присваивал
координаты точкам, мог уже изменить деталь. Ошибка не откатывает изменения;
повторять весь фрагмент автоматически нельзя. Сначала следует отдельно прочитать
текущее состояние. Здесь live-перестроение и изменение пользовательской детали
не выполнялись.

Ошибки `execute_python` теперь содержат `python_line` (номер строки переданного
кода, начиная с 1, включая пустые строки) и `error_type`. Для ошибки внутри функции
указывается строка внутри неё. Полный traceback, исходный код и локальные переменные
в диагностические поля не добавляются. Синтаксические ошибки также получают номер
строки; обычный `CAD_ERROR` не подтверждает отсутствие частичных изменений.

Полный пример только чтения передаётся модели в описании инструмента `execute_python`.
Он выбирает именно `Эскиз1`, обрабатывает отсутствие тел/сегментов и явно обозначает
нелинейные сегменты как неподдержанные. Координаты точек остаются в системе эскиза;
с bbox в системе модели их нельзя сравнивать без преобразования.

Проверено на установленной библиотеке типов SolidWorks 2025: у `IBody2` есть
`GetBodyBox` и нет `GetBoundingBox`; `GetStartPoint2`/`GetEndPoint2` возвращают
`VT_DISPATCH`, `ISketchPoint` содержит свойства `X/Y/Z`, у `ISketch` нет `GetName`.
Онлайн-страницы справки 2025 вернули HTTP 403; описание приблизительности bbox
дополнительно проверено через Context7 по [официальной справке](https://help.solidworks.com/2026/english/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IBody2~GetBodyBox.html).

Живое чтение исправленного примера через MCP прошло: одно тело, bbox
`[-2, -2, 0, 58, 38, 80]` мм, найден `Эскиз1`, прочитаны две линии с концами
`[0, 38, 0] → [0, 0, 0] → [58, 0, 0]` мм в системе эскиза. Геометрия и файлы
не изменялись. Локальный результат: `.superpowers/inspection-fix.json`.

После известной ошибки `execute_python` агент может запросить у модели ограниченное
исправление: максимум две попытки, с указанием номера строки и типа ошибки. Модель
должна сначала запросить read-only состояние или безопасную инспекцию, затем передать
только минимальное продолжение; исходный сценарий целиком автоматически не повторяется.
Неизвестный результат COM остаётся аварийной остановкой без исправления. Новый Python-код
в чате по-прежнему требует первого подтверждения для диалога и подключения; успешное
чтение bbox не меняет `execute_python` в инструмент независимой точной проверки геометрии.

## Разбор построения модели и чертежа 28.10.2026

Прочитаны четыре завершённых снимка прогонов через `GET /api/runs` работающего
приложения. История следующих ходов содержит предыдущие сообщения: повторение
ошибки в такой истории не означает новый COM-вызов. Пользовательские документы
при расследовании не изменялись, отдельный MCP для живых проверок не запускался.

| Ошибка | Подтверждённая причина | Предотвращение |
|---|---|---|
| `Несовпадение типов`, аргумент 8 | В `SelectByID2` передан `None` вместо COM `VT_DISPATCH` для Callout | Передавать `NOTHING`; литеральный `None` теперь отклоняется до доступа к CAD |
| Дуги основания проходят неверно | `Create3PointArc` получил начало, промежуточную точку, конец | Порядок API: начало, конец, точка на дуге; проверять замкнутость и касательность до вытягивания |
| `<unknown>.DraftAngle` | У `IExtrudeFeatureData2` нет такого свойства | Читать `GetDraftAngle(True)` в радианах и `GetDraftWhileExtruding(True)`; проверять интерфейс до изменения |
| `No module named 'requests'` | Сгенерированный код рассчитывал на отсутствующую зависимость | Предпочитать локальную библиотеку типов; для HTTP использовать стандартную `urllib.request` с timeout |
| `name 'tl' is not defined` | В прежнем исполнителе каждый вызов был независим | Внутри нового Run переменные сохраняются; после нового запроса или прямого вызова без сессии их нужно определить заново |
| Габаритный размер 170 вместо 200 мм | `SetArcEndCondition` вызван с индексами 0 и 1 вместо 1 и 2 | Литеральные неверные индексы блокируются; после записи читать оба условия и фактическое значение |
| Финальный прогон `failed` | API модели вернул HTTP 522 после уже выполненных CAD-действий | Это внешняя ошибка API; после восстановления связи сначала инспектировать состояние, не повторять построение целиком |

Для последнего размера история показывает: исходно 140 мм, затем 170 мм,
условия концов при правильных индексах — `(1, 3), (2, 1)`: один конец остался
в центре дуги. Два конца на внешних точках должны давать 200 мм. Этот вывод
относится к прочитанному результату вызова; промежуточный SLDDRW был сохранён
раньше, и его содержимое после этого отдельно не проверялось. Чертёж не завершён.

Сигнатуры и наличие методов сверены с установленной библиотекой типов
SolidWorks 2025 (major 33). Семантика точек дуги и нумерация концов проверены
через Context7 по официальной справке:
[Create3PointArc](https://help.solidworks.com/2026/english/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.ISketchManager~Create3PointArc.html),
[GetArcEndCondition](https://help.solidworks.com/2026/english/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IDimension~GetArcEndCondition.html).

`cadnext/python_preflight.py` разбирает AST и компилирует код внутри существующего
STA-задания **до** `_app()` и чтения ActiveDoc. В прямых вызовах API и форме
`GET(obj, "method", ...)` проверяются литеральные Callout/Index, включая именованные
аргументы прямых вызовов. Код не переписывается и не выполняется для проверки.
Диагностика содержит `python_line`, `phase="preflight"`, `changes_started=false`
и подсказку; эти поля получает и модель при ограниченном исправлении. Флаг означает,
что не исполнялся именно отклонённый фрагмент: предыдущие вызовы могли изменить CAD.
Поэтому модель может передать полную исправленную версию отклонённого фрагмента,
включая подготовку объектов. Для ошибки во время исполнения остаётся только
инспекция и минимальное продолжение. Пользовательское исключение того же класса,
поднятое внутри уже исполняемого кода, не получает отметку отсутствия изменений.

Динамические значения, вызовы через другие обёртки и реальная геометрия AST-проверкой
не проверяются. Правила распознаются по именам методов SolidWorks; это не полный
анализ типов произвольного Python.
Локальные вспомогательные классы с такими же именами методов подпадают под те же
ограничения литеральных аргументов; для собственных методов выбирай другие имена.
Инструкции модели требуют числовой сверки размеров,
привязок и масштабов, запрещают подменять ошибочный размер текстом. Они снижают риск
ошибки генерации, но не дают гарантии точного соответствия чертежу. `execute_python`
по-прежнему получает `unverified`, а неизвестный исход COM блокирует продолжение.
