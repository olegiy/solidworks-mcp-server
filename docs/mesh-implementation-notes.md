# Решения при внедрении STL/OBJ

Работа выполнена в `feat/mesh-to-cad`, исходная ревизия
`a5bf5384b23859e4fc450ad916233fe78173e8e5`.
Результаты исследования донора — [анализ ScanRuler](scanruler-donor-analysis.md),
этапы — [план](superpowers/plans/2026-11-01-mesh-to-cad.md),
порядок использования — [инструкция](mesh-to-cad.md).

## Принятые решения

1. Использован существующий checkout новой feature-ветки с его venv,
   без второго worktree. Это сохраняет подготовленное окружение; цена —
   необходимость отдельно следить за незавершёнными изменениями в том же каталоге.
2. Скрипты навыка, распознающие английские `Task`, заменены эквивалентными
   операциями Python/PowerShell для русского плана. Объём реализации тот же;
   цена — ручное ведение соответствия этапов и проверок в журнале.
3. Добавлен NetworkX 3.7: настоящие проверки сечений выявили необходимость
   `Path3D.discrete`. Цена — дополнительная зависимость BSD.
4. Первичный предел снижен до 250000 треугольников/вершин: опыт с почти
   миллионом граней потребовал 925 МиБ. Цена — большие сетки отклоняются.
5. Точность production CAD-триангуляции остаётся неизвестной. Подтверждения
   сигнатур и документации недостаточно для всей поверхности. Цена —
   положительное соответствие реального документа пока заблокировано.
6. CAD-экспорт ограничен исследовательскими бюджетами: 25000 треугольников,
   45 с cooperative deadline и 500000 COM-чтений. Начатый COM по-прежнему
   ожидается, таймаут не сбрасывается. Цена — сложные тела могут отклоняться.
7. Финальная проверка резервирует три вызова вместо двух: после вычислений
   нужно заново проверить документ/update stamp. Цена — один слот из лимита Run.
8. Помимо 50000 глобальных точек на сторону, каждая область получает256
   точек; максимум512 областей на сторону. Это защищает маленькие отверстия
   от потери в глобальном проценте. Цена — более сложные сетки дают unknown.
9. Очистка прерванного потока проверена на границе хранилища, отмена —
   браузером через API. Исключение генератора TestClient не моделирует
   разорванный ASGI-сокет. Цена — реальный транспортный обрыв остаётся
   отдельной ручной проверкой; не выдаётся за пройденный API-тест.
10. Переносится только текущий исходник, измерения прежних прогонов остаются
    историческими без архива заменённых байтов. Для нового исходника без Run
    сохраняется начальный допуск0.1 мм. Цена — для воспроизведения старого
    прогона нужен его оригинальный файл, а допуск нового следует проверить.
11. `mesh_smoke` выполняет только численное чтение, без режима мутации.
    Live-точность ещё не подтверждена и live-мутации не разрешены. Цена —
    отдельная приёмка на новой детали SolidWorks остаётся необходимой.
12. CAD/LLM-double проверяет интеграцию этапов, независимых чтений и численного
    сравнения с иной триангуляцией. Он не исполняет нативные CAD-операции.
    Цена — реальная редактируемость и качество построения внешним LLM
    остаются отдельными live-критериями.

## Дополнительные регрессии

Проверены восстановление ожидания обработки после перезагрузки, очистка
при закрытии проекта/отклонении импорта, сохранение преобразования и допуска,
разбор некорректной матрицы без500, смена единиц при одинаковом SHA256,
сохранение эталона до первого mesh-Run. Контракты v1 и старые проекты сохранены.

Итог финального обзора и проверки фиксируется в
[журнале верификации](verification.md). Ни live CAD, ни внешний LLM
в фикстурную приёмку не входят. Код AGPL ScanRuler не копировался.


## Финальный независимый обзор

Обзор gpt-6-astra выявил три Important, Critical/Minor отсутствуют.
Исправлены с воспроизводящими RED→GREEN тестами: общий achieved до окончания
mesh gate при Stop/лимите; запуск по прежнему источнику во время фоновой
замены; позднее переключение проекта/потеря черновика после отменённого Open.
Последнее проверяется и для связанного исходника, и для открытия только истории.
Запуск во время обработки замены получает409 до CAD.

Рецензент отдельно не оценивал реальную точность/полноту ITessellation
и способность внешнего LLM строить нативные редактируемые детали.
Решение: оба остаются явными live-критериями, production precision_known=false;
цена — фикстурная готовность не даёт гарантии точности или успеха живого построения.
Отложенных Minor нет.


Работа остаётся в запрошенной feature-ветке без слияния или публикации.
Временный журнал исполнения хранит промежуточные команды; его решения
перенесены в этот документ для дальнейшего анализа. Инструкция и план
не объявляют live-этап завершённым.
