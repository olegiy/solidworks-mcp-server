# Проверка ключей и хранения секретов — 25 октября 2026

В проверенных локальных данных настоящих ключей не обнаружено. Проверка не
обращалась к внешним моделям и не передавала значения ключей сканирующим сервисам.

Проверены все 248 доступных объектов Git: 145 blob (3 251 512 байт), 16 коммитов,
87 деревьев, включая недостижимые объекты; также 7 refs, reflog и метаданные Git.
Общие шаблоны токенов, приватных ключей, паролей и URL с учётными данными дали
только фиктивные значения в тестах. У remote-адресов нет встроенных credentials.
Использован локальный сканер; Gitleaks не установлен.

Отдельно выполнено точное локальное сравнение ключей двух сохранённых подключений
(один уникальный ключ) с содержимым всех 248 объектов Git (включая 145 blob),
20 файлов метаданных Git и 187 файлов рабочей области,
включая сборку и локальные артефакты, и пяти текстовых файлов данных приложения.
Проверялись обычное, UTF-16LE, URL-кодированное и base64-представления. Совпадений
и ошибок чтения нет; значения ключей и совпавшие строки в отчёт не записывались.
Окружения Python, node_modules и кэши не входят в точный поиск рабочей области.

Ключи хранятся в Windows Credential Manager (`cad_agent_next`), а JSON настроек
и публичный API возвращают только признак наличия ключа. Ошибки провайдера
не включают HTTP-заголовки, тело ответа или текст исходного сетевого исключения.

Исправлен риск переноса секрета между серверами: при изменении нормализованного
адреса API прежний ключ удаляется, если новый не передан явно. Добавление
завершающего `/` не считается сменой адреса. При неудачной записи настроек
восстанавливаются прежний профиль и ключ. Это проверено на временном тестовом
хранилище без изменения реальных credentials.

В `.gitignore` добавлены `.env`, файлы credentials/secrets/settings и форматы
приватных ключей. Это предотвращает обычное случайное добавление таких файлов,
но не заменяет проверку содержимого перед публикацией.

Границы: удалённые ветки GitHub не запрашивались; вывод относится к доступным
локальным данным. Это не полная проверка всех возможных уязвимостей. Внешний HTTP
по-прежнему разрешён настройками и не шифрует транспорт; у сохранённых подключений
передача ключей на внешний HTTP не обнаружена. Для облачного сервера следует
использовать HTTPS. Локальный Python-код сохраняет доступ к системе согласно
явно выбранной пользователем политике подтверждения на диалог.

`npm audit` с включённой проверкой TLS-сертификатов (`strict-ssl=true`) не обнаружил
известных уязвимостей в дереве npm-зависимостей. В исходном окружении запуска Node
была переменная `NODE_TLS_REJECT_UNAUTHORIZED=0`; для повторного аудита она установлена
в `1` только в процессе проверки. Проект её не задаёт. Python-транспорт модели
использует стандартную проверку сертификатов HTTPX и `trust_env=False`.
