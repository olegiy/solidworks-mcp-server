# Цикл Выполнения До Достижения Цели: План Реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выполнять CAD-задачу в цикле «действие → проверка → исправление» до достижения зафиксированных критериев либо явной безопасной остановки.

**Architecture:** Сохранить существующий последовательный Agent и проверки операций. Добавить контракт цели, локальные служебные инструменты фиксации требований/привязок и отдельную фазу оценки без инструментов мутации. Код рассчитывает итог и решает о завершении; vision-модель может подтверждать визуальные признаки, но не переопределяет числовые CAD-проверки.

**Tech Stack:** Существующие Python 3.12, asyncio, MCP, JSON Schema, FastAPI/Pydantic, React/TypeScript, pytest, Playwright. Без нового SDK, СУБД или зависимости для геометрического сравнения.

**Spec:** Согласованные требования пользователя в этом диалоге, раздел «Контракт решения» ниже; текущие инварианты в `AGENTS.md`, `docs/agent.md`, `docs/app.md`, `docs/models-and-privacy.md`. Отдельный design-файл в рамках планирования не создаётся.

## Контракт Решения

Подтверждено пользователем:

- Первый критерий — «Схожесть с требованиями», порог по умолчанию 100%. Это доля выполненных зафиксированных признаков, а не пиксельное или математически точное геометрическое тождество.
- Требования извлекаются автоматически из запроса/вложений, публикуются и фиксируются до первого изменения CAD. Недостающие обязательные размеры и противоречия требуют уточнения, а не угадывания.
- Измеримые размеры проверяются CAD-чтением. Недоступные таким чтениям визуальные признаки может подтверждать vision-модель; источник подтверждения обязательно показывается.
- По умолчанию: 10 оценок результата, остановка после 3 исправительных итераций без улучшения, 80 MCP-вызовов вместе с проверками. Параметры задаются до запуска.
- Цикл включён по умолчанию для CAD-задач; перед запуском есть явное отключение. Справочный ответ не получает выдуманный процент.
- При выбранной модели без Vision разрешено автоматическое переключение только на заранее назначенный Vision-профиль с сохранённым разрешением передавать ему задачу и изображения. Не выбирать произвольный профиль.
- Исследование MecAgent через REA — первый этап. Недоступная серверная реализация документируется как неизвестная и не блокирует собственный механизм.

Проектные решения этого плана:

- Одна оценочная итерация — свежая проверка текущего результата, не отдельный вызов инструмента и не каждая реплика модели. Первая оценка задаёт базу; три последующих оценки после исправлений без роста счёта останавливают цикл.
- Каждое требование имеет положительный целочисленный вес (по умолчанию 1). `score = 100 * passed_weight / total_weight`; unknown/failed не дают баллы, знаменатель не меняется. При пороге ниже 100 все обязательные требования всё равно должны пройти; порог может ослаблять только необязательные признаки.
- Схожесть — агрегат первого места; дополнительно показывать размерную точность, полноту требований, корректность модели, достаточность доказательств и запрошенные выходные файлы. Не усреднять обязательный неверный размер с успешной визуальной оценкой.
- Доступность признака из одного изображения не доказывает скрытую геометрию. Vision вправе вернуть unknown; отсутствие эталона/нужного вида не превращается в pass. Итог с vision-pass помечать «По CAD-проверкам и оценке модели», не «Геометрия доказанно идентична».
- Никакого универсального валидатора внутренней топологии в первой версии. Фиксированные CAD-проверки покрывают возможности существующего каталога; остальное — явно visual либо unsupported. Самовольный Python модели не является независимым числовым верификатором.
- Привязки к созданным CAD-объектам допускаются после построения, но не изменение целевых значений, весов, обязательности или эталона. Новые требования пользователя — новый Run.
- Справочная задача классифицируется при подготовке как informational с причиной; сервер запрещает ей CAD-мутации. Появилась необходимость строить — сначала зафиксировать CAD-контракт, не обходить оценку классификацией.
- Автомаршрутизация выполняется один раз перед Agent.start. Консервативно для запуска с включённой оценкой на non-Vision профиле сразу выбирать назначенный Vision-профиль, даже если подготовка позднее определит запрос как справочный. Это исключает передачу изображений non-Vision модели и смену провайдера посреди Run. Отображать фактическое подключение до отправки и в событиях; при отсутствии назначения не отправлять запрос и предложить его настроить либо отключить оценку.
- Уточнение завершает текущий Run без CAD-мутации с `goal.outcome=unknown`, `completion_reason=clarification_required`, `status=completed`; следующий ответ пользователя начинает новый Run. В UI явно «Нужно уточнение», а не «Цель достигнута».
- Сохранить старую `verification` как достоверность операций; отдельный `goal.outcome` не перезаписывает её. Успешный goal может содержать visual-подтверждения при `verification=unverified` для execute_python; обе отметки показывать без противоречивого утверждения о независимой проверке всего кода.

## Global Constraints

- Один активный Run, один MCP, один COM STA; только `com_call`, без параллельных CAD-вызовов и автоповторов мутаций.
- Не менять COM_TIMEOUT=55, poisoned/uncertain, владение процессами, stop/wait/aclose; не отменять начатую CAD-операцию и не запускать проверку после stop.
- `max_calls=80`, допустимо 1–1000; новые проверки входят в этот бюджет. Не увеличивать бюджет автоматически.
- Сохранить native tool IDs, возрастающий seq, SSE update/snapshot/replay/Last-Event-ID, остановку по request_id до ответа POST и pagehide.
- Profile неизменяем. Смена фактического API/модели требует нового PrivacyContext; параметры MCP восстанавливаются тем же контекстом, который их маскировал.
- Ключи только в Windows Credential Manager. В JSON/событиях нет секретов; изображения не обезличиваются, это явно указано при настройке авто-Vision.
- Новые UI-тексты ru/en по существующим i18n-паттернам; документы на русском, идентификаторы и новые комментарии кода на английском.
- Python-команды только `.venv\Scripts\python.exe`. В планировании исходники не изменяются. Коммиты и push только по отдельному запросу пользователя.

## Review Focus

- Модель выдумала успешные значения: числовой pass считается только приложением из свежего allowlisted CAD-ответа; тест задачи 2.
- Устаревший скриншот, сменившийся активный документ или изменённый эталон: не принимать старую оценку за текущую; тест задач 2 и 4.
- Повторяющиеся ответы «готово» без инструментов: конечное число оценок/модельных ходов, никакого бесконечного цикла; тест задачи 4.
- Авто-Vision назначен старому адресу или отозван во время подготовки: никакой отправки неразрешённому профилю и никаких CAD-мутаций; тест задачи 3.
- Восстановление старого sidecar и SSE с пропусками: не синтезировать успех и не выполнять инструменты повторно; тест задач 5 и 6.

## Задача 2. Контракт Цели И Чистый Оценщик

**Интерфейсы в `cadnext/evaluation.py`:**

- `EvaluationOptions`: enabled=True, target_similarity=100 (0 < value <= 100, finite), max_evaluations=10 (1–100), max_no_progress=3 (1–10).
- `GoalContract`: version=1, kind=cad|informational, requirements, reference_ids, ambiguities. До 64 требований; уникальные IDs, описание, источник (запрос/вложение), обязательность, weight=1 (1–100), method=cad|vision, expected/tolerance/unit для CAD, immutable contract_digest.
- `EvidenceRecord`: id, requirement_id, contract_digest, revision, document_identity, tool_call_id или image_ids, source=cad|vision, actual, status=pass|fail|unknown, reason. Не принимать модельные поля actual как результат CAD.
- `evaluate_goal(contract: GoalContract, evidence: list[EvidenceRecord], *, revision: int, target_similarity: float) -> GoalEvaluation`.
- `GoalEvaluation`: номер, revision, contract_digest, score (null если не было оценки), per_requirement, outcome=achieved|not_achieved|unknown, authority=cad|mixed|vision, evidence_ids, at.
- `update_progress(previous: GoalEvaluation | None, current: GoalEvaluation, no_progress: int) -> int`: строгое увеличение суммы весов pass сбрасывает счётчик; первая оценка не увеличивает его. Колебания ниже ранее достигнутого максимума не считаются новым прогрессом.

- [ ] Написать падающие тесты `test_similarity_requires_all_weight_at_100`, `test_required_dimension_blocks_lower_threshold`, `test_unknown_never_passes`, `test_stale_revision_or_contract_cannot_pass`, `test_visual_pass_is_labelled_not_geometric_proof`, `test_progress_uses_best_score_not_oscillation`; добавить malformed/duplicate IDs/NaN/Infinity/пустой CAD-контракт/изменение весов.

## Порядок И Граница Готовности

Выполнять 1 → 2 → 3 → 4 → 5 → 6 → 7. Задачи 3 и 4 сходятся на неизменяемом effective profile, поэтому интегрировать их последовательно. Не переносить неизвестные решения на исполнителя: изменение согласованных критериев, маршрутизации или безопасности требует отдельного решения пользователя.

Готово, когда пользователь видит фиксированные критерии, сервер не завершает CAD-задачу по одному тексту модели, несоответствие вызывает безопасное исправление, все исходы конечны и честно обозначены, а история/оценки восстанавливаются без повторного выполнения инструментов.

Не входит: универсальное сравнение B-rep, гарантия точности vision, неизменность CAD при ручном редактировании вне приложения, бесконечный цикл, дополнительный wall-clock timeout (сохраняются транспортные таймауты и согласованные счётчики), автоматический подбор другого API при сбое, live сетевое исследование чужого аккаунта, выполнение исходников MecAgent, изменение текущего MCP-каталога.
